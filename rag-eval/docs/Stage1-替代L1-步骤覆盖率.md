# Stage 1 补充：替代 L1（步骤覆盖率）

**结论先行**：在 leave-one-out 协议下（检索到的永远不是这道题本身），R 臂上下文覆盖了
**63.4%** 的解题步骤，X 臂（等长随机块）只有 **14.6%**，Δ = **+48.8pp [42.1, 55.6]**。
剔除「检索到同数值近似重复题」的子集后仍为 **+27.0pp**（R 44.7% vs X 17.7%）。
因此 Stage 1 判定中留空的 **ret-strong 现在有了直接 L1 证据**。

---

## 1. 为什么需要这个指标

Stage 1 的判定是「build（带条件）」，其中一条条件是：

> 补替代 L1 指标（检索结果里是否含可迁移解题步骤），否则「ret-strong」只是从 L2 反推。

原因：本题库语料下，`oracle_recall@k` 在 LOO 协议里**按定义为 0**——检索结果本来就不该
包含题目自身。原来的 L1（gold doc 命中）在这个协议下彻底失效，于是只能从「答对了」
反推「检索有用」，而答对可能来自参数记忆（N 臂 0.348 就是证据）。

换一个问法就有解：不问「有没有检索到这道题」，而问「**检索到的内容里，有没有解这道题
需要的推理步骤**」。

## 2. 指标设计（四层，每层挡一种伪信号）

| 层 | 做法 | 挡住的伪信号 |
|---|---|---|
| 1. 步骤化 | 解析按 `。；．\n` 切句；剥「解析：」标签；剔图片占位符与「故答案为 X」纯答案句；短散文碎片并入上一步，短算式碎片保留 | 把标签/图片标记/答案回声当成推理步骤 |
| 2. **残差匹配** | 每个步骤的 n-gram 减去**题干自身**的 n-gram，只用剩下的部分去匹配 | 同题型相邻题题干高度相似 → 题面照抄被白送覆盖 |
| 3. 双口径 | literal（数值保留）/ skeleton（数字连续段归一为 `#`） | 只用 literal 会漏掉「方法相同但数值不同」的迁移；只用 skeleton 会把通用骨架当精确命中 |
| 4. 零基线 | 主口径 = ΔStepCov = R − X | 数学语料共享大量套话（"先求"、"所以"），任何块都能蹭到覆盖率 |

其它实现约束：

- **τ 两阶段冻结**：`--select-tau` 只允许在 dev 上执行，规则预注册为「最小 τ 使 X 臂判别口径
  覆盖率 ≤ 0.15」；`--apply` 只读冻结文件，文件缺失或非 dev 选出即拒绝运行。eval 上的 τ
  敏感性只作稳健性展示，不用于重选。
- **n-gram 与 LaTeX**：k=3；匹配前必须先做 LaTeX 归一——doc 文本里保留着 `\div`、`\times`，
  不归一会变成字面 "div"，与解析里的 `÷` 永远匹配不上（这是实现时踩到的真实 bug，
  修复前 O 臂算式覆盖率只有 0.30，修复后 1.00）。
- **不可定义即拒绝给数**：某 query 若无可用步骤，覆盖率为 `null` 而非 0，并从配对 bootstrap 中剔除。

## 3. 结果

### 3.1 步骤级（主口径）

| 臂 | dev（n=100） | eval（n=200） |
|---|---|---|
| N 无上下文 | 0.0000 | 0.0000 |
| X 等长随机 | 0.1248 | 0.1462 |
| **R 检索（LOO）** | **0.6354** | **0.6340** |
| O gold 解析 | 0.9755 | 0.9971 |
| **ΔStepCov = R−X** | **+0.5106** [0.416, 0.604] | **+0.4877** [0.421, 0.556] |

dev→eval **没有收缩**（0.511 → 0.488），与主效应 ΔREL 的「22.1pp → 11.9pp 砍半」形成对比：
检索**供给**的内容是稳定的，波动出现在模型**利用**它的环节。

O 臂 0.997 是上界健全性检查：gold 解析自身的步骤当然应当全覆盖。

### 3.2 算式级（辅助口径）

把解析里的算式抽成单元，比较「算子骨架」是否出现（`28÷4=7` 与 `100÷5=20` 同骨架 `#÷#=#`）。

| 口径 | X | R | O | Δ=R−X |
|---|---|---|---|---|
| 任意算式（算子≥1） | 0.391 | 0.677 | 0.999 | +0.286 |
| **复合算式（算子≥2）** | 0.147 | 0.525 | 0.999 | **+0.377** [0.282, 0.473] |
| 算式字面（同数值） | 0.006 | 0.326 | 0.997 | — |

「任意算式」的零基线高达 0.39，因为 `#×#=#` 这类骨架在数学文本里到处都是；**复合算式**
（算子≥2）才有区分度，故以它为主。字面命中 X≈0 → 该口径衡量的就是「检索到同数值的重复题」。

### 3.3 重复题分层（必须披露）

题库语料存在大量近似重复题（同题不同 qid）。用「R 臂是否命中同数值算式」识别：

| 子集 | n（占比） | R 步骤覆盖 | R 复合算式 |
|---|---|---|---|
| 检索到同数值重复题 | 64（37.4%） | 0.940 | 0.925 |
| 未检索到（纯迁移） | 107 | 0.447 | 0.300 |

**纯迁移口径**：在「没检索到重复题」的 107 条上，R = 0.447 vs X = 0.177，**Δ = +0.270**。

结论：头号数字（+48.8pp）里约有一半来自「检索到了同一道题的副本」，但**去掉这一半仍然是
+27.0pp**——迁移是真实存在的，只是没有裸数字看起来那么夸张。

### 3.4 效度检验（这项指标能预测答对率吗）

| 检验 | 结果 |
|---|---|
| V1 同臂相关：R 臂覆盖率 vs R 臂 token-F1 | r = **0.339**，ρ = 0.441（n=198） |
| V1 对照：X 臂同样计算 | r = 0.104（噪声臂不该有强相关，符合预期） |
| V2 配对增益：(R−X) 覆盖率 vs (R−X) F1 | r = **0.211**（n=198），Δcov=+0.488 / ΔF1=+0.121 |
| V3 分档单调 | 覆盖=0 → F1 0.302（n=59）；覆盖=1 → F1 **0.642**（n=112） |
| V4 复合算式 vs F1 | r = 0.316（n=128） |

判据（预注册：V1 与 V2 均需 r>0.2）→ **指标可用**，但只是**中等强度**：
覆盖率是「供给」的度量，不是「必定答对」的保证。

### 3.5 关键分离：供给 ≠ 利用

按 KC 把两个增量放在一起看（eval）：

| 模块 | n | ΔStepCov | ΔF1 |
|---|---|---|---|
| 行程 | 6 | +0.667 | **+33.3pp** |
| 几何 | 18 | +0.556 | **+23.1pp** |
| 计数 | 30 | +0.432 | +15.6pp |
| 应用题 | 55 | +0.462 | +15.2pp |
| 组合 | 21 | +0.369 | **0.0pp** |
| **计算** | 29 | **+0.516** | **−4.5pp** |

计算模块：检索**确实提供了**所需算式与步骤（覆盖 +0.516），但 F1 反而下降 4.5pp
（R 0.612 vs X 0.657）。组合模块同理：覆盖 +0.369，增益 0。

这解释了 Stage 1 的负结果，也修正了直接拿覆盖率当「该不该检索」判据的冲动：

> **覆盖率是必要条件的近似，不是充分条件。** 计算类题模型本来就会（N 臂已 0.598），
> 检索带来的额外上下文只是干扰；组合题虽然相似度高，但 LOO 后剩下的「同类不同题」帮不上忙。

产品含义：检索开关不能只看「上下文是否覆盖步骤」，要看「这类题的增益历史」。

## 4. 断言与剔除

| 断言 | dev | eval |
|---|---|---|
| A1 N 臂覆盖率为 0 | ✅ | ✅ |
| A2 R 臂不含本 query 的 gold doc（LOO 完好） | ✅ | ✅ |
| A3 零步骤仅限「解析不可用」（纯图片/纯答案） | ✅（0 剔除） | ✅（2 剔除） |
| A4 O 臂 > X 臂（上界健全性） | ✅ 0.976 vs 0.125 | ✅ 0.997 vs 0.146 |
| A5 每个 chunkId 都能按配置分块参数还原 | ✅ | ✅ |

被剔除的 2 条（eval）：`q-xes-1917` 解析是「方法一：[图] 方法二：画流程图：[图]」，
`q-xes-3558` 解析只有一个答案数字。二者属于语料本身不可用，不是切分失败。

步骤统计：中位 **1 步/题**（本题库 56% 的解析只有一句），题面回声占比 0.9%。
单步题在句子级只有 0/1 二分——这正是需要算式级子口径的原因。

## 5. 稳健性

τ 与 k 的敏感性（dev）：

| τ | 0.30 | 0.35 | **0.40** | 0.45 | 0.50 | 0.55 | 0.60 |
|---|---|---|---|---|---|---|---|
| X | 0.223 | 0.172 | **0.125** | 0.074 | 0.072 | 0.037 | 0.030 |
| R | 0.673 | 0.654 | **0.635** | 0.590 | 0.590 | 0.581 | 0.569 |
| Δ | 0.450 | 0.482 | **0.511** | 0.516 | 0.518 | 0.544 | 0.539 |

k=3 是事先设定的默认值（中文 3-gram），τ=0.40 由预注册规则选出。改变 k：

| k | τ=0.4 下 Δ |
|---|---|
| 3 | 0.510 |
| 4 | 0.554 |
| 5 | 0.557 |

Δ 在 0.45–0.57 区间稳定，**结论不依赖具体超参**。

## 6. 复现

```bash
# 1) dev 上选 τ 并冻结（唯一允许的调参入口）
node src/stage1/stepCoverageRun.js --config configs/rag-eval-config.json \
  --split dev --contexts data/stage0/dev-pilot-loo --select-tau

# 2) eval 上应用冻结的 τ（未参与任何选择）
node src/stage1/stepCoverageRun.js --config configs/rag-eval-config.json \
  --split eval --contexts data/stage1/eval --apply

# 3) 效度检验
node src/stage1/l1Validity.js --eval-dir data/stage1/eval \
  --steps data/stage1/steps/step-coverage-eval.json

# 测试
node --test test/stepCoverage.test.js   # 19 例
```

产物：

| 文件 | 内容 |
|---|---|
| `data/stage1/steps/step-coverage-tau.json` | 冻结的 τ + 完整扫描曲线 + 规则说明 |
| `data/stage1/steps/step-coverage-dev.json` | dev 逐 query/逐步骤明细（含残差与包含度） |
| `data/stage1/steps/step-coverage-eval.json` | eval 同上 + 重复题分层 + 断言 |
| `data/stage1/steps/l1-validity.json` | V1–V4 效度检验 |
