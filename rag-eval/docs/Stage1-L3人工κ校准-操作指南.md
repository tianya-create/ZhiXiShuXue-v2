# L3 人工 κ 校准：操作指南

> 目的：回答一个问题——**LLM judge 的打分，换成人类来判，还成立吗？**
> 不成立时，一切以 L3 为依据的结论（尤其「R 比 X 好」）都必须降级。
>
> 本文是可直接照做的流程，附命令与判读规则。预注册规则在 §7，**开始评分前先读一遍，中途不得改**。
>
> **状态：已执行（2026-11-12）。** 加权 κ=0.970 [0.937, 0.992]，闸门 `primary`，结果与限制见 **§11**。下文 §1–§10 保持评分前的原文，未回改。

## 1. 为什么必须做（这三条缺一不可）

| 已做的检查 | 它能证明什么 | 它不能证明什么 |
|---|---|---|
| 10% 二次重判，一致率 1.000 | judge 是确定性的（同输入同输出） | judge 判得**对** |
| judge 与生成器同模型 | — | 无自评偏好（实际存在） |
| L2 token-F1 与 L3 方向一致率 96% | 两个口径不矛盾 | 两者**同错**时无法发现（都偏爱「格式像答案」的输出） |

更要紧的是第三点：真正威胁结论的不是「judge 整体偏松」，而是**judge 对检索臂（R）特别宽松**。整体偏松只会平移所有臂，ΔREL 不变；按臂差异化偏松会**凭空造出效应**。所以校准要同时回答两件事：

1. **一致性**：judge 与人的一致程度（κ）；
2. **差异化偏差**：`bias(R) − bias(X)`，其中 `bias = mean(judge − human)`。

### 2.1 为什么又出了一版（v1 的三个硬伤）

初版直接把题库原文灌进 CSV，人打开后有三类「看不见」：

| 现象 | 真实原因 | v2 怎么处理 |
|---|---|---|
| 题面像乱码：`$$63$$只猫咪`、`46\times 99` | 题库原文是 LaTeX，CSV 不做渲染 | 转成 `63只猫咪`、`46×99`（`src/util/readable.js`，191 项测试覆盖） |
| 题目里冒出 `question_3124-image_0` | 这是内部图片文件名，图没随文本导出 | 题面换 `【图1】`，图放到 `images/` 并在审阅器里直接显示 |
| 「如图所示…」但看不到图 | 55/201 条依赖图片，题库把图存成独立 PNG | 从官方包提取 43 张本批用到的图；`needsImage=1` 明确标注 |
| pred 被截断到 60 字符 | v1 生成时截断，导致长答案无法判分 | 取消截断，完整显示 |

> **重要**：转换只在展示层做。语料分块、BM25 索引、步骤覆盖率匹配仍用原文——否则等于评测中途换数据，冻结清单失效。

### 2.2 依赖图片的题怎么判

58/201 条 `needsImage=1`。这不是校准瑕疵，而是评测设定的一部分：**四臂（N/X/R/O）模型都看不到图**，所以这些题的 pred 系统性偏低是必然的。

判分时：对着审阅器里显示的原图判 pred 对不对（判的是「模型答案 vs 标准答案」，不是「模型能不能看图」）。判完工具会自动把「含图 / 不含图」两组 κ 分开报——如果含图组明显更低，说明差异来自题目本身不可解，而不是 judge 判不准。

构成：主样本 **195 条**（按 25% 随机抽，四臂 45–54 条）+ 富集样本 **6 条**（judge 判 1 分的，用于看中间档）。

**为什么是 25% 而不是原来的 10%**：κ 的 95% CI 半宽 ≈ `1.96·√(po(1−po)/n)/(1−pe)`。按 po≈0.85、pe≈0.5 估算，n=64 时半宽约 0.18——若真值 0.7，下界会掉到 0.52，直接跨过 0.60 门槛，等于白测。n≈196 时半宽压到 0.10。命令可复算：

```bash
node src/stage1/calibration.js --required-n --po 0.85 --pe 0.5 --half-width 0.10
# → 约需 196 条（当前池 800 条 → rate≈0.245）
```

## 3. 谁来评、评多少

| 方案 | 得到什么 | 代价 |
|---|---|---|
| **两人各判 195 条（推荐）** | judge–人 κ + **人–人 κ（上限参照）** | 约 2×90 分钟 |
| 一人判 195 条 | judge–人 κ | 约 90 分钟 |
| 一人判 100 条（下限） | judge–人 κ，CI 半宽约 0.14 | 约 45 分钟，只能支撑「方向性」结论 |

**为什么建议两人**：κ 的参照点不是 1.0。若两个人之间 κ 只有 0.65，那 judge–人 0.65 就已经是「和人一样好」，不该被苛责。只有一个人时，无法区分「judge 不准」与「rubric 本身模糊」。

两人评分时，把第二人的分数填在新增的 `humanScore2` 列（工具会自动算人–人 κ）。**两人必须独立评、不许商量**，否则上限参照被污染。

## 4. 评分流程（每条约 20–30 秒）

### 4.1 推荐：用审阅器（约 60–90 分钟）

直接双击 `data/stage1/eval/judge/human-calibration-review.html`（Chrome / Edge 均可，无需装任何东西）。

- **打分**：题面下方三个按钮 `0 / 1 / 2`，或键盘直接按 `0` `1` `2`
- **翻页**：`J` / `K` 或 ↑↓；`N` 跳到下一条未评
- **看图**：依赖图的题会在题面下方直接显示图片，不需要另开文件夹
- **备注**：每题一个输入框，写「为什么这样判」（选填但建议填有分歧的）
- **进度**：自动存浏览器本地，关掉再开不丢；右上角「只看未评」可过滤
- **导出**：右上角「导出 CSV」→ 得到 `human-calibration-blind.filled.csv`（三列：`itemId,humanScore,note`）

### 4.2 备选：用 Excel 填 CSV

```bash
# 复制一份工作副本，原表保持未填状态（可追溯）
cp data/stage1/eval/judge/human-calibration-blind-v2.csv data/stage1/eval/judge/human-calibration-blind.filled.csv
```

- 公式已转可读，但 **Excel 里看不到图**：`needsImage=1` 的行，按 `images` 列的文件名去 `images/` 目录双击对应 PNG
- `humanScore` 只填 `0` / `1` / `2`，不留空、不写文字
- 表里没有 `arm` 与 `judgeScore`，这是刻意的——看到机器分再打，κ 测的就是确认偏差

### 4.3 两种方式都适用的规矩

1. **先读 §8 的评分标准原文**，只看这一份，不要自创标准。
2. 拿不准的：照常给分，在 `note` 写一句原因（例如「多空题只对 1 个空」「单位不同但数值对」）。**不要留空**，留空会让整份表判定为未完成。
3. **不要**打开 key 文件、不要猜 `arm`。
4. 中途休息可以，但**不要**评了一半去改 rubric 或改判分口径；那等于中途换尺子。

现实预期：pred 中位长度只有 2 个字符，绝大多数一眼可判；201 条约 60–90 分钟。

## 5. 必须提前定死的边界规则

这些是「换尺子」的高发区。**评分开始前确认，开始后不改**：

| 情形 | 定死为 | 理由 |
|---|---|---|
| `0.5` vs `1/2`、`12.0` vs `12` | 2 分（等价） | rubric 原文已写明等价形式 |
| 数值对、单位省略或不同（`米` vs `厘米` 但数值已换算） | 2 分 | 数值等价即正确 |
| 多空题（`81 144 324`）只对一部分 | **1 分**（部分正确） | rubric 的 1 分档就是为此存在 |
| 多空题全错 | 0 分 | — |
| 答案顺序与 gold 不同但集合相同 | 2 分 | 判集合不判顺序 |
| 复述题干、没给最终数值 | 0 分 | 未作答 |
| 空 `pred` | 0 分 | 未作答 |
| 答案含多余错误结论（对的部分 + 错的补充） | 1 分 | rubric 原文「含多余错误结论」 |
| 中文数字 / 阿拉伯数字（`十` vs `10`） | 2 分 | 等价 |

**一条重要提醒**：本数据只有 9/800 条被 judge 判 1 分（1.1%）。如果你也几乎不用 1 分，说明这个三档 rubric 实际上退化成二档——那就应当**明确改成二档 rubric 并写 revision**，而不是留着一个没人用的档位假装三分制。

**工具会自动做的事**：
- 富集样本（`enriched:true`）**不并入主 κ**，只单列 `enrichedOnly`——否则 κ 有偏；

- 缺填 / 非法值（如 `3`）/ 未知 `itemId` 一律列出并使闸门失败，**不静默修复、不自动填机器分**。

## 7. 判读规则（预注册，评分前不得改）

### 7.1 主指标

| 指标 | 为什么看它 |
|---|---|
| **加权 κ（quadratic）** | 主判据。相邻分歧（0↔1）比跨档分歧（0↔2）罚得轻，符合「部分对」的语义 |
| Cohen κ | 参照，与加权 κ 差距大说明分歧集中在相邻档 |
| **Gwet AC1** | 治 κ 悖论。两方都偏向同一类时 κ 会被压低，AC1 不会。**κ 低而 AC1 高 = 分布问题，不是判读问题** |
| PABAK | 完全不看机会一致，作旁证 |
| `biasIdx` | 谁更宽松（有方向），与下面的有符号偏差互补 |

### 7.2 三档闸门

| κ_w（quadratic） | 结论 | 对 Stage 1 判定的影响 |
|---|---|---|
| **≥ 0.60 且 CI 下界 ≥ 0.45** | `primary` | L3 可作主证据之一，`ΔREL` 可由 L3 交叉确认 |
| **0.40 – 0.60** | `directional` | L3 只报方向；判定不得以其为唯一依据，须由 L2 + 替代 L1 支撑 |
| **< 0.40** | `unusable` | L3 作废；结论回落 L2 + 替代 L1，且需在报告中明示「L3 不可用」 |

### 7.3 差异化偏差护栏（独立于 κ）

| 条件 | 动作 |
|---|---|
| `\|bias(R) − bias(X)\| ≥ 0.25` 分 | **必须做敏感性重算**：用有人的那部分样本，把 R/X 的分数换成人类分，重算 ΔREL 并报符号是否翻转 |
| `< 0.25` | 未触发，正常报 ΔREL |

这一条比 κ 更直接：κ=0.8 也可能掩盖「R 臂系统性偏松 0.3 分」。

## 8. 评分标准原文（与 judge 逐字相同，sha256 `f7c77f19…`）

```
2 = 完全正确：数值/表达式与参考答案等价（单位可省略，等价形式如 0.5 与 1/2 视为相同）
1 = 部分正确：思路或部分要素正确，但最终答案错误、不完整或含多余错误结论
0 = 错误：答案与参考答案不符、答非所问、拒答或为空
```

**不要改这份文本**。改了就是换尺子，judge 的 800 条全部作废、必须重判，并写 config revision。

## 9. 常见错误

1. **先看机器分再打分** → κ 变成「确认偏差测量」。本工具已把 `judgeScore` 从盲表移除，别去开 key 文件。
2. **只挑有争议的样本评** → κ 失去无偏性。主样本必须随机；想看争议样本用 `--enrich-ones`，且单列。
3. **留空当 0 分** → 工具会判「未完成」并拒绝出结论（这是故意的）。
4. **把富集样本并进主 κ** → 中间档被过度加权，κ 虚高。工具已强制分离。
5. **拿重判一致率当 κ 报** → 两者不是一回事，见 §1。
6. **κ 低就改 rubric 重测** → 这叫「为通过而调尺」，必须在报告里披露调了几次、每次 κ 多少。
7. **CI 不看** → n=64 时 κ 的点估计几乎没有信息量；本表 n=195 才把半宽压到 0.10。

## 11. 结果（2026-11-12 已执行）

**输入**：`human-calibration-blind.v1-raw.csv` 201 条全部填分（0 分 75 / 1 分 16 / 2 分 110），缺填 0、非法 0、未知 id 0。主 κ 用 195 条随机样本，6 条富集单列。

**命令**：

```bash
node src/stage1/calibration.js --score \
  --sheet data/stage1/eval/judge/human-calibration-blind.v1-raw.csv \
  --key   data/stage1/eval/judge/human-calibration-key.jsonl \
  --strata data/stage1/eval/judge/human-calibration-blind-v2.csv
```

**结果**（报告 `data/stage1/eval/judge/kappa-report.json`）：

| 指标 | 值 | 读法 |
|---|---|---|
| po | 0.959 | 原始一致率 |
| **加权 κ(quad)** | **0.970 [0.937, 0.992]** | 主判据，是门槛 0.60 的 1.6 倍 |
| Cohen κ | 0.921 [0.852, 0.979] | 与加权 κ 差 0.05，分歧集中在相邻档 |
| Gwet AC1 | 0.945 | 与 κ 接近 → 高分不是分布假象 |
| PABAK | 0.918 | 不看机会一致仍很高 |
| `biasIdx` | 0.021 | 无系统性宽松方 |
| `gate.level` | `primary` | L3 可作主证据之一 |
| `biasAlarm` | false（−0.064） | 未触发敏感性重算 |

分臂（`judge − human`，0–1 口径）：N −0.020 / X +0.021 / R −0.011 / O 0.000。
分层：不含图 n=138 κ_w=0.967、含图 n=57 κ_w=0.973——**依赖图片的题没有拉低一致性**，`needsImage` 分层规则可保留但非瓶颈。

### 11.1 必须披露的软肋：中间档

混淆矩阵（行 = 人，列 = judge）：

| 人 \ judge | 0 | 1 | 2 |
|---|---|---|---|
| **0** | 74 | 0 | 1 |
| **1** | 5 | 3 | 2 |
| **2** | 0 | 0 | 110 |

- 「对/错」边界几乎完美：人判 2 的 110 条 judge 全判 2；人判 0 的 75 条只有 1 条被判 2（98.7%）。
- 「部分正确」几乎不成立：人判 1 的 10 条里 judge 只同意 3 条；judge 在整份 195 条里**只用了 3 次 1 分**，实际已退化为二值判断。
- 加权 κ 对这种分歧罚得轻（1↔0 只罚 0.25），所以 0.970 主要证明的是**「能不能判对错」**，不是**「能不能判部分对」**。

**因此的使用边界**：ΔREL（均值差）可放心由 L3 支撑；但任何「部分正确比例」「中间档分布」的表述都不能用 L3 出，要报就报对/错口径，或先细化 rubric 的中间档（=换尺子，须写 revision 并重判 800 条）。

### 11.2 非必须但做了的敏感性重算

护栏未触发，仍用人类分重算了一遍以核对方向（`node src/stage1/biasSensitivity.js`，报告 `bias-sensitivity.json`）：

| 口径 | ΔREL | 95% CI（按 queryId 簇，B=4000） |
|---|---|---|
| 人类分 | +0.0625 | [−0.134, +0.260] |
| judge | +0.0303 | [−0.170, +0.231] |

符号一致，人类分不比 judge 更保守/宽松，**不存在「judge 对 R 臂偏松造出 ΔREL」**。注意子样本每臂仅 44–53 条，CI 跨 0 属预期——本表只做方向核对，全量估计仍是 200 题四臂的 +11.9pp。

### 11.3 三条不回流纪律（已遵守）

1. 没因 κ 高就删掉 L2 token-F1 或替代 L1——三条证据并存，L3 只加不改；
2. 没改 rubric、没重挑样本，`f7c77f19…` 仍是评分原文；
3. 中间档的弱证据写进了结论的限制条件，而不是「κ=0.97 所以 judge 完全可信」。

### 11.4 一处追溯性瑕疵（如实记录）

本次是**直接在 `human-calibration-blind.v1-raw.csv` 上填分**，没有按 §4.2 先复制工作副本，所以「未填分原件」被覆盖了。影响可控：

- 盲表内容本身可复核：`human-calibration-blind-v2.csv` 与前者的 `itemId` 集合、顺序完全一致（201 条），可作空白基线；
