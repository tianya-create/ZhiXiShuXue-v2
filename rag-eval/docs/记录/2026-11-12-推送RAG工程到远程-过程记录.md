## 一、过程记录

### 1. 落位决策

`rag-eval/` 原本是独立于 `zhiXiShuXue/` 的同级目录，而它要进的是 `zhiXiShuXue` 这个仓库。两个选择：

因此把工程复制为 `zhiXiShuXue/rag-eval/`，并在根 `README.md` 的「目录结构」与新增的「RAG 受控评测」小节里挂了入口。

### 2. 网络：GitHub 走不通，换代理

| 尝试 | 结果 |
|---|---|
| 默认（env 代理 `127.0.0.1:64414`） | `CONNECT tunnel failed, response 502` |
| 清空 `HTTP(S)_PROXY/http(s)_proxy` 直连 | `Failed to connect to github.com:443`（21s 超时） |
| 沙箱外直连 | 同样失败 → 不是沙箱策略问题，是本机到 GitHub 不通 |
| 探测常见本地代理端口 | **7897 返回 200**（Clash 混合口），其余 7890/10809/10808/1080/8080 全失败 |

最终用 `git -c http.proxy=http://127.0.0.1:7897` 单次指定，**没有改全局/仓库配置**，避免代理关掉后 git 全线报错。若以后长期要推，可考虑仓库内 `git config http.proxy`，但需接受代理未开时的失败。

### 3. 入库范围：先量体积，再定排除项

`rag-eval` 全量 **1.1G**，绝大部分是数据集：

| 路径 | 体积 | 处理 |
|---|---|---|
| `data/xes3g5m/*.tar.gz` | 446M | 排除（可重新下载，且受数据许可约束） |
| `data/xes3g5m/kt4eqg/` | ~100M | 排除（KT4EQG 解压产物） |

### 4. 凭据排查（这一步最要紧）

复制进来的 `data/xes3g5m/` 里带着两个下载过程残留文件：

- `gd_cookies.txt`（495B，Google Drive cookies）
- `gd_page.html`（2.4KB，Drive 中转页）

**提交前已删除**，并在 `.gitignore` 里加了 `gd_cookies.txt` / `gd_page.html`。同时全仓扫描（`sk-[A-Za-z0-9]{16,}`、`AKIA…`、`BEGIN PRIVATE KEY`、`password=`）无命中；`configs/*.json` 里只有「API key 只从环境变量读取」的说明，没有值。文档里出现的 `sk-ws-…` 是脱敏占位符，不是真 key。

### 5. 一个坑：父仓库 `.gitignore` 会吃掉所有 CSV

仓库根 `.gitignore` 有全局 `*.csv`（原本是为了不提交数据集清洗产物）。而本次最该入库的恰恰是 `human-calibration-blind.v1-raw.csv`（人工评分表）、`-v2.csv`、`kappa-report` 依赖的分层表——不加例外，κ 结果就不可复核。

处理：在 `rag-eval/.gitignore` 末尾加 `!*.csv`。Git 的否定规则在同目录层级优先，实测 `git add -An` 里三份 CSV 都在，`.parquet` 仍被排除。

### 6. 提交与推送

git commit -F -                     # 见 commit message
