# 2026-11-12 L3 人工 κ 校准工具与流程 — 过程记录

## 一、任务

用户问「怎样做 L3 人工 κ 校准」。目标不只是给步骤说明，而是把需要的材料与工具一次性做到可执行：盲评表、密钥文件、κ 计算器、判读闸门。

## 二、先盘现状（发现三个必须先修的问题）

读了 `data/stage1/eval/judge/` 与 `src/stage1/judge.js` 后确认：

| 问题 | 证据 | 后果 |
|---|---|---|
| 旧表未盲评 | `human-calibration-sheet.csv` 表头为 `queryId,arm,question,goldAnswer,pred,judgeScore,humanScore,note` | 人看到臂名与机器分再打分 = 确认偏差，κ 失去解释力 |
| 样本量不足 | 64 条（10%） | κ 的 95%CI 半宽约 0.18；真值 0.70 时下界 0.52，直接跨过 0.60 门槛 → 测了也判不了 |
| 中间档为空 | 全部 800 条里 judge 只判过 9 条 1 分（1.1%），64 条样本中 0 条 | 「部分正确」档无法估计，三档 rubric 实际退化为二档 |

另发现 `pred` 被截断到 60 字符（影响 0.5% 条目），一并修掉。

## 三、做了什么

### 1. 新增 `src/stage1/calibration.js`

四块能力：

- **抽样与出表**：`buildCalibration` 用 `sha256(seed|queryId|arm)` 生成确定性均匀数，**与输入顺序无关**（乱序输入产出逐字节相同的表与密钥）；选中项按该随机数排序编号 `c-001…`，使 `itemId` 与臂无关。
- **盲性**：盲表列固定为 `itemId,question,goldAnswer,pred,humanScore,note`，不含 `arm` 与 `judgeScore`；臂与分数只写 `human-calibration-key.jsonl`。
- **统计**：Cohen κ、加权 κ（linear/quadratic）、Gwet AC1、PABAK、二元化 `biasIdx`/`prevalenceIndex`、逐臂一致率与有符号偏差；CI 用**按 `queryId` 的簇自助**（同题 4 条答案相关，不能按条独立重采）。
- **闸门**：三档（primary / directional / unusable）+ 独立的差异化偏差护栏；缺填、非法值、未知 id 一律使闸门失败。

### 2. 富集样本强制单列

`--enrich-ones N` 补抽 judge 判 1 分的条目。这类补样会让中间档被过度加权，因此 `evaluateCalibration` 内部**自动把 enriched 条目从主 κ 剔除**，只在 `enrichedOnly` 块单列（含逐条明细，便于看人是否也认为「部分对」）。

### 3. 替换 judge 里的旧出表逻辑

`src/stage1/judge.js` 的 `writeCalibrationSheet` 改为委托 `writeCalibration`，默认抽样率 0.25。旧表重命名为 `human-calibration-sheet.deprecated.csv`，防止误填。

### 4. 出真实盲评表

```
node src/stage1/calibration.js --build --rate 0.25 --enrich-ones 10
→ 201 条：主样本 195（N 52 / R 45 / O 54 / X 50）+ 富集 6（judge=1）
→ judge 分布 0:79 / 1:9 / 2:113
```

### 5. 配置声明协议（rev5）

`judge.calibration` 记录抽样率、n、seed、盲性开关、簇自助参数、三档门槛与护栏阈值。本次**未改动** generator/retriever/threshold/chunk/rubric，eval 产物仍对应 rev2 快照。

## 四、踩的坑

1. **加权 κ 测试写成反向断言**：误以为加权后 κ 会低于无权 κ。实际 quadratic 让相邻分歧变便宜 → κ 应更高。改成手算三档值钉死（无权 0.3333 / linear 0.4444 / quad 0.5333）。
2. **PABAK 用例造错数据**：想要 po=0.75 却给了全一致样本（po=1.0）。改为 15 条一致 + 5 条分歧。
3. **样本计数口径不一致**：初版把富集条目算进「缺填」，输出出现「已评 0/195，缺填 201」。改为 `rated/expected` 与 `mainRated/mainExpected` 两套计数分开报。
4. **Windows 下 `/tmp` 被解析成 `D:\tmp`**：端到端验证改用项目内 `data/stage1/.tmp-kappa/`，测完删除。
5. **矩阵退化**：早期构造的加权 κ 用例里人方全给 2 分，导致 pe=1、κ 恒为 0，看起来像公式错，实际是数据退化。测试数据必须让双方边际都非退化。
