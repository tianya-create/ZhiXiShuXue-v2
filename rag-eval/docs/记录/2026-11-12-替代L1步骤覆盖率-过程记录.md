# 过程记录：替代 L1（步骤覆盖率）——2026-11-12

## 一、任务

补上 Stage 1 判定中留空的条件 1：**在 leave-one-out 协议下给出 ret-strong 的 L1 直接证据**。
原 L1（gold doc recall）在 LOO 下按定义为 0，必须换一个不依赖文档身份的度量：
「检索到的上下文里，有没有解这道题需要的推理步骤」。

约束：零新增 LLM 调用（全部输入是已落盘的 contexts.jsonl + 题库解析），可逐位复现。

## 二、做了什么

### 1. 新增 `src/metrics/stepCoverage.js`

四层设计，每层针对一种具体的伪信号：

| 层 | 实现 | 挡住的伪信号 |
|---|---|---|
| 步骤化 | 按 `。；．\n` 切句；剥「解析/解/答：」标签；剔 `[图:...]` 占位符与「故答案为 X」纯答案句；短散文碎片并入上一步，短算式碎片（含数字+算子）保留；去重 | 标签、图片标记、答案回声被当成推理步骤 |
| **残差匹配** | 步骤 n-gram 集合减去题干 n-gram 集合，只用残差去匹配；残差占比 <25% 判为「题面回声」并从判别口径剔除 | 同题型相邻题题干相似 → 题面照抄被白送覆盖 |
| 双口径 | literal（数值保留）/ skeleton（数字连续段→`#`） | literal 漏「方法同数值不同」；skeleton 会把通用骨架当精确命中 |
| 零基线 | 主口径 ΔStepCov = R − X | 数学套话（"先求"、"所以"）让任何块都能蹭到覆盖率 |

辅助口径 `expressionCoverage`：抽 `a op b = c` 算式单元，比较**算子骨架**是否出现在检索块
（字符串包含而非 n-gram，算式是短符号串，结构相等才有意义）；`literal` 子口径用于识别
「检索到同数值的近似重复题」。复合算式（算子≥2）才作主口径——「任意算式」的骨架
`#×#=#` 到处都是，X 臂零基线高达 0.39。

### 2. 新增 `src/stage1/stepCoverageRun.js`（两阶段强制分离）

- `--select-tau`：仅允许 dev，扫 τ 网格，按预注册规则「最小 τ 使 X 臂判别口径覆盖率 ≤ 0.15」
  选出并**冻结**到 `step-coverage-tau.json`（内含 τ、规则、完整扫描曲线、k、残差阈值、
  指标实现 sha256）。
- `--apply`：仅读冻结文件；文件不存在、`basedOn !== 'dev'` 或 `frozenBeforeEval !== true` 一律拒绝运行。

不变量检查（每次运行都断言，不过即 exit 3）：

| 断言 | 内容 |
|---|---|
| A1 | N 臂（空上下文）覆盖率为 0 |
| A2 | R 臂 docIds 不含本 query 的 gold doc（LOO 完好） |
| A3 | 零步骤仅限「解析不可用」（纯图片/纯答案），且已从聚合剔除 |
| A4 | O 臂（gold 解析自身）> X 臂（上界健全性） |
| A5 | 每个 chunkId 都能用配置的分块参数（300/40）从语料还原 |

配对 bootstrap 复用 `bootstrapArms`（groupKey=queryId，2000 reps，seed 42）。

### 3. 新增 `src/stage1/l1Validity.js`（效度检验）

预注册判据：V1（同臂覆盖率 vs token-F1）与 V2（(R−X) 覆盖 vs (R−X) F1）都要 r>0.2。
另给 V3 分档单调、V4 算式级相关。

### 4. 新增 `test/stepCoverage.test.js`（19 例）

扫描会退化成常数（这个 bug 真实发生过，见下）。

## 三、踩坑与修复

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | **doc 文本里的 LaTeX 未归一** | O 臂（gold 解析自身）算式覆盖率只有 0.30；`\div` 在匹配归一里变成字面 `div`，与解析里的 `÷` 永不相等 | `normalizeForMatch` 先做 `normalizeMath` 再剥标点；O 臂修复后 → 1.00 |
| 2 | **括号被剥掉** | `(8-2)×(8-2)` 与 `8-2×8-2` 变成同一个串，语义不同的算式互相命中 | 匹配字符集加入 `()`，并补 `%^` |
| 3 | **τ 扫描退化成常数** | `selectTau` 读的是行里已存的覆盖率字段（在临时 τ=0.5 下算好的），不管 τ 怎么变结果都一样 → 错误选出 τ=0.3（真实 X=0.22 > ceiling 0.15） | 改为用 `_detail`（与 τ 无关的逐步骤最大包含度）在每个 τ 上重算；修复后选出 τ=0.40（X=0.125） |
| 4 | **图片占位符被当步骤** | `[图:analysis-4407-0]` 出现在步骤列表里 | `splitSteps` 增加 `IMAGE_PLACEHOLDER` 过滤 |
| 5 | **纯算式碎片被丢** | `1+2+9；1+3+8` 这类短解析全部被「过短」规则丢弃 → 零步骤 | 短碎片若含「数字+算子」则保留；纯散文碎片才并入上一步 |
| 6 | **A1 断言误报** | 零步骤 query 的覆盖率为 `null`，`null !== 0` 被判违例 | 断言改为 null-safe；同时把「零步骤」拆成两类：解析不可用（可接受，剔除）/ 切分失败（不可接受） |
| 7 | **题面回声阈值不灵** | 用「步骤对题干的 3-gram 包含度 ≥0.75」判回声，实测改写后的题面只有 0.37，一条都抓不到 | 改为**残差占比**判据（非题干 n-gram 占比 <25%），语义更准：这一步是否携带题干之外的信息 |
| 8 | **算式级零基线过高** | 「任意算式」X=0.39，Δ 虽正但绝对水平太吵 | 主口径改为复合算式（算子≥2），X=0.15 |
| 9 | 测试期望错两处 | `splitSteps` 实际切出 3 步（我按 2 写）；`selectTau` 因 `>=` 语义在 0.5 处仍算覆盖 | 按真实语义修正期望值，不迁就实现改判据 |

## 四、结果

### dev（n=100，τ=0.40 在此选出）

| 臂 | 步骤覆盖 | 复合算式 |
|---|---|---|
| N | 0.000 | 0.000 |
| X | 0.125 | 0.166 |
| R | 0.635 | 0.688 |
| O | 0.976 | 1.000 |

ΔStepCov = **+0.5106 [0.4163, 0.6037]**；ΔExpr = +0.5218 [0.3945, 0.6429]（配对 64）。

### eval（n=200，只应用冻结 τ）

| 臂 | 步骤覆盖 | 复合算式 |
|---|---|---|
| N | 0.000 | 0.000 |
| X | 0.146 | 0.147 |
| R | 0.634 | 0.525 |
| O | 0.997 | 0.999 |

- ΔStepCov = **+0.4877 [0.4211, 0.5564]**，p=0.001；ΔExpr = **+0.3774 [0.2817, 0.4733]**。
- dev→eval **不收缩**（0.511 → 0.488），与主效应 ΔREL 的「22.1pp → 11.9pp 砍半」相反：
  检索**供给**是稳定的，波动在模型**利用**环节。
- 重复题分层：37.4% 的 query 检索到同数值近似重复题（其 R 覆盖 0.940）；剩下 107 条
  R 0.447 vs X 0.177 → **纯迁移 Δ=+0.270**。
- 效度：V1 r=0.339（ρ=0.441）、V2 r=0.211；分档 覆盖=0 → F1 0.302，覆盖=1 → F1 0.642。
- 关键分离：计算模块 ΔStep=+0.516 但 ΔF1=−4.5pp → **供给 ≠ 利用**。
- 五项断言 dev/eval 全过；eval 剔除 2 条「解析不可用」（纯图片 / 纯答案）。
- 测试 **149/149**（新增 19）。
