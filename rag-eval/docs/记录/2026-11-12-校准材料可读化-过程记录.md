# 2026-11-12 人工校准材料可读化（题目乱码 / 缺图）— 过程记录

## 0. 起因

用户打开 `human-calibration-blind.csv` 反馈：**「有些题目看不到，乱码了，或者没有图片」**。

## 1. 排查：三类「看不见」各自的真实原因

先做量化，不猜：

```bash
node -e "统计 question 列的 LaTeX / 图片占位符 / 空题面"
```

| 现象 | 实测 | 根因 |
|---|---|---|
| 题面像乱码 | 177/201 含 `$$…$$`，33 条含 `\times` 等命令 | 题库原文就是 LaTeX，CSV 不渲染 |
| 冒出一串英文 | 55/201 题面里嵌 `question_3124-image_0` | 这是**内部图片文件名**，图没随文本导出 |
| 「如图所示」但没图 | 55 条引用图，共 43 张唯一 PNG | 图存在 `XES3G5M/metadata/images/`，此前只解压了 `questions.json` |
| 题目被截断 | **仅 1 条** | 当初生成时 `slice(0,120)`；影响面比预想小 |
| 编码乱码 | BOM `ef bb bf` 正常 | 不是编码问题 |

结论：主因是**LaTeX 未渲染 + 图片未提取**，不是编码，也不是普遍性截断。

## 2. 做了什么

### 2.1 新增 `src/util/readable.js`（展示层转换）

LaTeX → 可读文本：

- 去 `$$` 定界符（**直接删不换成空格**：换空格会把 `$$63$$只` 变成 `63 只`，制造虚假分词）
- `\times`→`×`、`\div`→`÷`、`\cdot`→`·`、`\leq`→`≤`、`\pi`→`π` 等 30 余条命令
- `\dfrac{a}{b}`→`a/b`、`\sqrt{x}`→`√(x)`、`\text{…}`→内容（迭代处理嵌套，最多 6 层）
- `^2`→`²`（unicode 上标）、`\left(`→`(`、`\quad`→空格、`\,`→删
- 命令后的空格一并吃掉：`46\times 99` → `46×99`（LaTeX 里该空格无语义）
- 图片占位符 → `【图N】`，同时 `extractImageRefs()` 返回真实文件名
- 未知命令去反斜杠保留名字，**不留一堆 `\foo` 给人看**

**关键约束**：只用于展示。语料分块、BM25 索引、步骤覆盖率匹配仍用原文——否则等于评测中途换数据，冻结清单失效。

### 2.2 提取题图

```bash
# 只抽本批 201 条样本用到的图，不全量解压
node -e "生成 .imglist.txt（43 个文件路径）"
tar -xzf data/xes3g5m/XES3G5M.tar.gz \
  -C data/stage1/eval/judge/images \
  --strip-components=3 -T data/stage1/eval/judge/.imglist.txt
```

结果：43 张 PNG，754 KB（全量 3,870 张，只取需要的）。

### 2.3 新增 `src/stage1/buildReviewSheet.js` → 两份材料

**（A）`human-calibration-blind-v2.csv`** —— Excel 可开

列：`itemId, needsImage, images, question, goldAnswer, pred, humanScore, note`
（新增 `needsImage` 标注是否要图、`images` 列文件名；`pred` 不再截断）

**（B）`human-calibration-review.html`** —— 单一文件审阅器，1.3 MB

- 图片 base64 内嵌（不依赖外部文件，发给别人也能用）
- 公式已可读、题图直接显示在题面下方
- 点按钮或键盘 `0/1/2` 打分，`J/K`/↑↓ 翻题，`N` 跳未评
- 进度存 `localStorage`，刷新不丢
- 「只看未评」过滤、一键导出 `human-calibration-blind.filled.csv`（三列）
- **不含 `arm`、不含 `judgeScore`**（盲评约束在生成时用正则校验过）

### 2.4 打分工具加 needsImage 分层

`src/stage1/calibration.js`：
- `evaluateCalibration({ ..., strata })` 新参数；表内有 `needsImage` 列则优先用
- 返回 `byNeedsImage: { noImage: {...}, withImage: {...}, unknown }`
- CLI 新增 `--strata <v2.csv>`（审阅器导出的三列 CSV 缺该列时靠它补）
- 单条样本不返回 `null` 而是 `{n:1, insufficient:true}` —— 否则会被误读成「这组不存在」

**为什么值得单独分层**：58/201 条依赖图片，而四臂（N/X/R/O）模型**都没有视觉输入**，这些题的 pred 系统性偏低是设定使然。混在一起算 κ，会把「这题本来判不了」伪装成「judge 判不准」。

模拟数据（85% 一致性）验证分层有效：不含图 κ_w=0.910，含图 κ_w=0.782。

### 2.5 v1 改名为数据源

`human-calibration-blind.csv` → `human-calibration-blind.v1-raw.csv`

理由：它现在只是 v2 的生成输入，留在同目录容易被 Excel 误点。`buildReviewSheet.js` 默认输入随之改为 v1-raw，避免「拿产物当输入」的循环。

## 3. 踩到的问题

| 问题 | 修法 |
|---|---|
| `$$` 换成空格导致 `63 只猫咪` | 改为直接删 |
| `\times 99` 后空格残留 → `46× 99` | 命令替换时用 `\s*` 吃掉尾随空格 |
| 命令按字母序替换会让 `\le` 吃掉 `\leq` 前缀 | 按命令长度降序替换 |
| 测试里 `n.missing.length` 报 undefined | `n.missing` 是数字不是数组，改断言 |
| 单条分层组 `subStats` 返回 null → `.n` 崩 | n=1 时返回结构体并标 `insufficient` |
| 默认文件名改动导致 5 个测试失败 | fixture 同步改名，并用 `DEFAULT_SHEET` 常量收敛 |
| HTML 里 `</script>` 注入风险 | `JSON.stringify` 后 `<` 转 `\u003c` |
