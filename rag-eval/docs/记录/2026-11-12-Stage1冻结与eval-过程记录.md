## 一、本次范围

## 二、过程记录

### 1. 先量断言，再写代码

四项断言里唯一不确定的是 `docClusterDisjoint`（dev/eval 的 oracle doc 是否落在同一近重复簇）。先跑一次性检查：

```
dev 簇数 100  eval 簇数 200  交集 0
多成员簇 381（全库）
```

交集为 0，说明 100/200 抽样没撞上近重复题，可以冻结。若不为 0，就必须在冻结前剔除相关 eval query——冻结后动 eval 集 = 破坏预注册。

### 2. 写冻结脚本 `src/stage1/freeze.js`

设计要点：

- **拒绝式冻结**：`stage0Preflight` 四值任一为 null、`thresholds.strongDeltaRel` 为 null、任一断言为 false → exit 2，不写 `frozenAt`、不写 manifest。
- **先写配置再取哈希**：`frozenAt` 与 `leakageAssertions` 要先落到 config 文件里，再对落盘后的文件取 sha256，否则 manifest 里的 config sha 和实际跑的不是同一份。
- **哈希自校验**：manifest 里同时记「配置声明的哈希」和「实物文件哈希」，`promptTemplateSha256` / `corpus.manifestSha256` 不一致就拒绝。

第一次运行就撞上一个口径问题：`corpus.manifestSha256` 之前存的是「解析后对象的 sha」，而 manifest 里要的是「文件字节 sha」。

```
old sha256:ad789a3f…   ← sha256OfJson(parsed)
new sha256:8bd487fc…   ← sha256OfText(file bytes)
```

改配置文件里的值（不是改判据）后重跑，冻结通过。

### 3. 冻结结果

```
[S1] dev=100 eval=200
[S1] 断言：query 簇 true｜doc 簇 true（dev 簇 100）｜few-shot true（0 例）｜LOO 索引 true（查 200 条）
[S1][FROZEN] data/stage1/freeze-manifest.json
[S1] config sha=sha256:9ebb0c316de8cc0b…
[S1] 阈值：σ=0.0209 strongDeltaRel=0.0418 覆盖率=0.92
```

断言 4 是**逐条实测**：对 200 条 eval query 各跑一次 LOO 检索，确认返回的 R 上下文里没有 gold docId（不是看配置开关）。

冻结后立刻把配置快照存成 `configs/frozen/rag-eval-config.rev2.json`，并核对：

```
snapshot sha  sha256:9ebb0c316de8cc0b… 
manifest sha  sha256:9ebb0c316de8cc0b…   match: true
```

### 4. 解封并跑 eval

```bash
node src/stage0/runStage0.js \
  --config configs/rag-eval-config.json \
  --dev data/evalset/eval-queries.json \
  --out data/stage1/eval \
  --exclude-self --concurrency 8
```

解封动作写进 `data/evalset/audit-log.jsonl`（目的、字段、条数、`usedForTuning:false`）。

耗时 2m42s，2,400 次调用，失败 0。

### 5. 写 L3 judge `src/stage1/judge.js`

要点：

- rubric 逐字冻结，sha256 `f7c77f19…`；judge prompt 单独再算一个 sha。
- **盲评**：prompt 里只有题目 / 参考答案 / 待评答案，不含臂名与上下文（有测试断言 `!p.includes('R 臂')`）。
- 空答案程序判 0，不调用模型（省钱且可审计）。
- 10% 样本二次重判，报 `exactAgreement`。
- 解析器三级降级：JSON → `score: n` 正则 → `null`（**不冒充 0 分**），越界分数（3）也不采信。

### 6. 配置改动（rev2 → rev3）的合规处理

judge 在冻结时是 null，现在要补，必然改 config。做法：

1. 先归档 rev2 快照（已核对 sha 与 manifest 一致）；
2. 把 `judge` 段填满、`revision` 改 3，并在 `_revision_note` 里写明「仅新增 judge 配置，未改 generator/retriever/threshold/chunk」；
3. `data/stage1/eval-run.json` 里同时记录 rev2 快照 sha 与 freeze-manifest sha，保证「跑的是哪版」可追溯。

### 7. 跑 judge

```bash
node src/stage1/judge.js --config configs/rag-eval-config.json \
  --eval-dir data/stage1/eval --concurrency 8 --rejudge-rate 0.1
```

800 条待评 + 70 条重判 = 870 次调用，1m18s，800/800 解析成功。

### 8. 踩到的坑（本次）

| # | 现象 | 处理 |
|---|---|---|
| 1 | 冻结脚本因 corpus manifest 哈希口径不一致而拒绝冻结 | 统一为文件字节 sha（不是解析对象 sha） |
| 2 | judge 重判一致率 1.000，看起来「完美」 | 不当作可靠性证据：只说明 judge 确定性，可靠性靠人工 κ，报告里明确写了 |
| 3 | 空答案若走模型会浪费调用且可能被判 1 分 | 程序判 0，`parsed:'empty'` 留痕 |
