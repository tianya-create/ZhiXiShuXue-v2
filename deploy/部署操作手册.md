# 智析数学 V1.0 · 部署与运维手册

> 面向对象：项目所有者  
> 目标：把 `https://github.com/tianya-create/zhiXiShuXue` 部署到腾讯云轻量应用服务器  
> 预计耗时：首次约 40 分钟（含买服务器、等待镜像构建）

---

## 〇、先看结论：你买的服务器要什么配置

| 项目 | 建议值 | 说明 |
|---|---|---|
| 产品类型 | 腾讯云**轻量应用服务器** | 比 CVM 便宜、带宽大、够用 |
| 地域 | 上海 / 广州 / 北京 | 就近选择 |
| 镜像 | **Ubuntu 22.04 LTS** 或 Debian 12 | 别选 CentOS（已停维护） |
| CPU / 内存 | **2 核 4G** | 2核2G 构建时会内存不足，强烈建议 4G |
| 系统盘 | 60 GB SSD | 镜像 + 数据足够 |
| 带宽 | 4 Mbps 起 | 5-8 Mbps 更流畅 |
| 价格参考 | 新用户首年约 100~200 元 | 常有"轻量应用服务器特惠"活动 |

> ⚠️ **不要买 2核2G**：前端 vite 构建峰值内存约 1.5~2GB，加上 Docker 和 Nginx，2G 极易 OOM 构建失败。

## 一、购买服务器（腾讯云控制台）

1. 打开 <https://cloud.tencent.com/product/lighthouse>
2. 点「立即选购」，按上表选配置
3. **镜像选择**：应用镜像 → 「Docker CE」官方镜像（省去手动装 Docker），或在系统镜像里选「Ubuntu 22.04」
   - 如果选了 Ubuntu 纯净镜像，登录后执行第 3 步的 `init-server.sh` 会自动装 Docker
4. 设置 root 密码（或绑定 SSH 密钥），**务必记住**
5. 付款后，在「轻量应用服务器」控制台记下**公网 IP**

---

## 二、放行端口（最关键，90% 的人卡在这）

腾讯云轻量服务器有**独立于系统防火墙的「防火墙」面板**，默认只开 22。

**控制台 → 轻量应用服务器 → 点进你的实例 → 「防火墙」标签页**，添加规则：

| 应用类型 | 协议 | 端口 | 来源 |
|---|---|---|---|
| SSH | TCP | 22 | 全部 IPv4 |
| HTTP | TCP | 80 | 全部 IPv4 |
| HTTPS | TCP | 443 | 全部 IPv4 |

> 💡 如果后面要做域名 + HTTPS，443 也必须放行（本手册默认先用 80 端口 HTTP 访问）。

## 三、连接服务器并初始化环境

### 3.1 连接服务器

在你自己的电脑上打开终端（Windows 可用 PowerShell 或 Git Bash）：

```bash
ssh root@你的服务器公网IP
# 首次连接输入 yes，然后输入你设置的密码
```

### 3.2 上传项目代码

**方式 A：直接 git clone（推荐，最省事）**

服务器上执行：

```bash
# 克隆代码（含我修改好的部署配置分支需要先推送，见文末「十一、代码同步说明」）
git clone https://github.com/tianya-create/zhiXiShuXue.git zhixi
cd zhixi
```

> 如果仓库里还没有我的部署配置改动，请先按「十一、代码同步说明」把改动推送到 GitHub，或改用方式 B 上传。

**方式 B：本地打包上传（不想动 GitHub 时用）**

在**你本地电脑**的项目目录执行：

```bash
# 打包（排除 node_modules 等）
cd D:/迅雷云盘/WorkBuddy/2026-10-15-14-04-28
tar --exclude='zhixi-project/node_modules' \
    --exclude='zhixi-project/frontend/node_modules' \
    --exclude='zhixi-project/backend/node_modules' \
    --exclude='zhixi-project/frontend/dist' \
    --exclude='zhixi-project/.git' \
    -czf zhixi-deploy.tar.gz zhixi-project

# 上传到服务器
scp zhixi-deploy.tar.gz root@你的服务器公网IP:/root/
```

服务器上解压：

```bash
cd /root && mkdir -p zhixi && tar -xzf zhixi-deploy.tar.gz -C zhixi --strip-components=1
cd /root/zhixi
```

### 3.3 安装 Docker 环境

```bash
# 如果买的是 Docker CE 镜像，可跳过；否则执行：
sudo bash deploy/init-server.sh
```

脚本会自动完成：安装 Docker、docker compose、配置**腾讯云内网镜像加速**、放行系统防火墙。

## 四、配置环境变量（填写 AI Key）

在服务器项目目录执行：

```bash
cd /root/zhixi
cp .env.example .env
vim .env
```

按 `i` 进入编辑，填写你的**阿里云百炼 API Key**（在 <https://bailian.console.aliyun.com/> → API-KEY 管理 获取）：

```ini
LLM_API_KEY=sk-你的密钥
AI_TUTOR_API_KEY=sk-你的密钥
BAILIAN_API_KEY=sk-你的密钥
```

首次部署还必须把 `.env` 中的 `JWT_SECRET`、`SETTINGS_SECRET`、`APP_SECRET` 替换为随机长字符串，并填写至少 12 位的 `ADMIN_PASSWORD`。生产环境首次启动只创建管理员账号，教师和学生请在管理端创建或导入。

填完按 `Esc`，输入 `:wq` 回车保存。

> 💡 **暂时没有 Key 也能部署**，只是"AI 小智""智能出题"功能会报错，登录/作业/题库等核心功能正常。后续补上 Key 后 `docker compose restart backend` 即可生效。

## 五、一键部署

```bash
cd /root/zhixi
sudo bash deploy/deploy.sh
```

脚本会依次：
1. 检查 Docker 环境
2. 准备 `.env` 和持久化目录
3. **构建镜像**（首次约 3~8 分钟，耐心等待）
4. 启动 `backend`（Node 22 + Express）和 `web`（Nginx）容器
5. 自动健康检查，并打印访问地址

看到 `部署完成！` 就成功了。

## 六、验证访问

浏览器打开：

```
http://你的服务器公网IP
```

首次登录使用用户名 `admin` 和 `.env` 中填写的 `ADMIN_PASSWORD`。登录后先在“用户管理”创建或导入教师、学生和班级。

### 打不开？按顺序排查：

| 现象 | 原因 | 解决 |
|---|---|---|
| 浏览器一直转圈/超时 | 安全组没放行 80 | 回到「二、放行端口」添加规则 |
| 502 Bad Gateway | 后端启动失败 | 服务器执行 `docker compose logs backend` 看报错 |
| 白屏但页面有响应 | 前端资源 404 | 确认镜像构建成功：`docker compose logs web` |
| `node:sqlite` 相关报错 | 用了 Node 20 镜像 | 确认 `Dockerfile` 是 `node:22-alpine` |

查看实时日志：

```bash
cd /root/zhixi
docker compose logs -f backend    # 后端日志
docker compose logs -f web        # Nginx 日志
docker compose ps                 # 容器状态
```

## 七、日常运维命令

```bash
cd /root/zhixi

# 查看服务状态
docker compose ps

# 重启（改完 .env 后执行）
docker compose restart backend

# 停止 / 启动
docker compose down
docker compose up -d

# 更新代码后重新部署
git pull
docker compose up -d --build

# 查看磁盘占用
docker system df
docker system prune -f          # 清理无用镜像（谨慎）
```

### 数据备份（重要！）

你的数据在两个目录，**定期备份**：

```bash
cd /root/zhixi
tar -czf ~/backup-$(date +%F).tar.gz backend/database backend/uploads
```

- `backend/database/` — SQLite 数据库（题库 270 万题、用户数据等）
- `backend/uploads/` — 用户上传的试卷文件

这两个目录已通过 docker volume 挂载到宿主机，容器重启**不会丢失**。

## 九、我为你修复的项目问题清单

部署前我发现并修复了以下问题（详见项目内改动）：

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | **`Dockerfile` 用 `node:20`** | 🔴 后端 `node:sqlite` 模块在 Node 20 不存在，服务**100% 启动崩溃** | 升级为 `node:22-alpine` 并开启 `--experimental-sqlite` |
| 2 | **原 Dockerfile 只启动后端** | 🔴 前端 build 后无人托管，**页面根本无法访问** | 重构为三段式：前端构建 → 后端 → Nginx 托管+反代 |
| 3 | **缺 Nginx 配置** | 前端、API、WebSocket 无法统一入口 | 新增 `deploy/nginx/default.conf`，反代 `/api`、`/ws`、`/uploads` |
| 4 | **compose 只挂载 database** | 🟠 uploads 目录未持久化，**重启丢失用户上传文件** | 挂载 `backend/uploads` |
| 5 | **后端端口直接暴露公网** | 🟠 5001 可被绕过 Nginx 直接访问 | 改为 `expose`，仅容器网络内可达 |
| 6 | **前端 `three` 依赖未声明** | 🟠 一旦组件被引用，构建立即失败 | 补入 `frontend/package.json` |
| 7 | 无健康检查、无时区设置 | 🟡 定时任务时间错误、无法自动感知故障 | 加 HEALTHCHECK + `TZ=Asia/Shanghai` |

### ⚠️ 遗留安全问题（涉及业务代码，我未擅自修改，请留意）

1. ~~**JWT 密钥硬编码**~~ ✅ **已修复**：密钥改为从 `backend/config/auth-secret.js` 读取环境变量
   `JWT_SECRET`，`.env` 中已写入随机值；同时补上 `backend/middleware/auth.js` 统一鉴权，
   封堵了原先"只信任 `x-user-id` 请求头"导致的**越权漏洞**（任何人伪造身份即可读写任意账号数据）。

2. **初始管理员密码**：`.env` 中的 `ADMIN_PASSWORD` 仅用于首次初始化，务必使用独立强密码并妥善保管；首次登录后按学校账号规范创建教师和学生。

3. **`tmp_patch_*.py` 脚本**：仓库根目录有若干临时修复脚本，属于开发残留，部署不受影响，但建议清理以保持整洁。

## 十、账号与密码运维

### 10.1 忘记密码怎么处理（已实现）

学生忘记密码时，**不支持自助找回**（未接入短信/密保），走"找班主任"流程：

1. 学生在登录页看到提示：**"忘记密码？请联系班主任或管理员重置"**
2. 班主任登录教师端 → **学生管理** → 对应学生行点击 **"重置密码"** 按钮（仅能重置**本班**学生）
3. 系统生成 10 位随机密码并弹窗展示，班主任**转告学生**，学生首次登录后建议自行修改

管理员可重置任意学生。接口：`POST /api/teacher/students/:id/reset-password`
（校验班级归属，写审计日志 `RESET_STUDENT_PASSWORD`）。

> 注意：重置的新密码**只显示一次**，弹窗关闭后需再次重置才能获得新密码。

### 10.2 登录账号在哪里看

**（1）看账号列表（用户名 / 姓名 / 角色）**

- 页面方式：用管理员登录 → 左侧 **「用户管理」**（对应 `frontend/src/views/admin/Users.vue`）
- 命令方式：

```bash
# 管理员登录拿 token 后查全部账号
curl -s "http://127.0.0.1/api/admin/users?pageSize=100" -H "Authorization: Bearer <token>"
```

**（2）看密码**

密码在数据库里是 **bcrypt 单向哈希**存储的，无法查看明文。首次初始化仅创建管理员账号：用户名为 `admin`，密码取自 `.env` 的 `ADMIN_PASSWORD`。之后教师、学生均应由管理员在“用户管理”创建或导入；忘记密码时请使用对应的重置功能。

> `ADMIN_PASSWORD` 仅在数据库为空时生效。已有数据库不会被部署过程覆盖。

### 10.3 数据持久化范围（重点）

所有业务数据（用户、班级、学生、作业、答题记录、错题本、知识点、VARK 档案、适配决策与长期校正记录等）与题库均落盘到
`backend/database/questions.sqlite` 的独立数据表中。
**容器重启、服务器重启都不会丢数据**（已在服务器实测：重置密码 → 重启 → 新密码仍有效）。

两个 SQLite 连接均已开启 `journal_mode=WAL` + `busy_timeout=5000`，避免偶发
`database is locked` 导致定时落盘失败。
