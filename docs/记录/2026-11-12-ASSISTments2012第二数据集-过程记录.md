### 2. 数据获取

官方页面核对后确认下载入口为 Google Drive（`drive.usercontent.google.com/download?id=1cU6Ft4R3hLqA7G1rIGArVfelSZvc6RxY`）。

- 归档：`2012-2013-data-with-predictions-4-final.zip`，576,365,408 字节，SHA-256 `7bb18f93…572445`
- 内层：`2012-2013-data-with-predictions-4-final.csv`，3,009,494,391 字节，SHA-256 `1d06aee9…5464db`
- 校验：zip 中央目录 entry CRC-32 `0x8f51cc70`，`zipfile.testzip()` 通过，解压后重算 CRC 一致

关键命令参数（下载器）：

```python
URL   = ".../download?id=1cU6Ft4R3hLqA7G1rIGArVfelSZvc6RxY&export=download&confirm=t"
TOTAL = 576365408     # Content-Length
N     = 12            # 并发分块
PROXY = "http://127.0.0.1:7897"
```

### 3. 踩坑与修复（详见 `backend/实验结果文件/assist2012-gcn-dkt-v1/deviation-log.md`）

| # | 问题 | 原因 | 修复 |
|---|---|---|---|
| D1 | 分块拼接后 zip CRC 失败，解压在压缩流 35,651,657 处报 `invalid block type` | 两个后台下载任务同时写同一 `.parts`，`have` 读数竞争；Google 端点忽略 Range 的结束边界 | 单进程 12 线程 + 独占目录 + 读满即断 + CRC 自愈（定位坏块只重下该块） |
| D2 | 按行读 CSV 列数不匹配 | `actions` 列是引号包裹的多行文本 | 新增 `scripts/lib/csvStream.js` 状态机解析器（只物化目标列），两链路共用 |
| D3 | 构图时报 `File size (3009494391) is greater than 2 GiB` | `readFileSync` 整块算哈希超过 Buffer 上限 | 改为 4 MB 分块喂 `crypto.createHash` |
| D4 | manifest 三处统计口径错误 | `sequenceCount` 取成学生数；`short-sequence.removed` 重复扣减；带 skill 行数标签错 | 改为链式扣减 + 用 `(学生,知识点)` 组数；**数据未变**（`interactions.csv` 前后同为 `8155ff18…`） |

### 4. 清洗（`scripts/ingest-assistments2012.js`）

```bash
node --max-old-space-size=6144 backend/scripts/ingest-assistments2012.js \
  --input backend/datasets/raw/2012-2013-data-with-predictions-4-final.csv \
  --out backend/datasets/assist2012
```

规则：`attemptId=problem_log_id`（启动断言唯一）／`kpCode=a12-s<skill_id>`／`correct` 只收 `0|1`／按 `(studentId,start_time,problem_log_id)` 稳定排序／剔除 `(学生,知识点)` 交互数 <2 的组。

### 5. 划分、目标与构图

```bash
# 每种子 validation 目标（不含 test）
node backend/scripts/buildAssist2012ValTargets.js \
  --interactions backend/datasets/assist2012/interactions.csv \
  --graphs-root "backend/实验结果文件/assist2012-gcn-dkt-v1" --seeds 42,43,44,45,46

# 每种子构图（读一遍 3GB 原始文件）
for s in 42 43 44 45 46; do
  node --max-old-space-size=6144 backend/scripts/buildAssist2012SkillGraph.js \
    --raw backend/datasets/raw/2012-2013-data-with-predictions-4-final.csv \
    --interactions backend/datasets/assist2012/interactions.csv \
    --manifest backend/datasets/assist2012/manifest.json \
    --seed $s --out "backend/实验结果文件/assist2012-gcn-dkt-v1" \
    --targets "backend/实验结果文件/assist2012-gcn-dkt-v1/seed-$s/val-targets.json"
done
```

### 6. 预检与判定

```bash
node backend/scripts/graphCoveragePrecheck2012.js --interactions ... --graphs-root ...   # exit=3
```

### 4. 判定

`protocol-not-applicable-graph-too-sparse`。原因不是模型，而是数据结构：一题一 skill、一次作答一行，2009 的「同题共标注」边规则无从成边。

- 不训练、不生成 test 目标、不填冻结记录、不做协议 commit
- 允许的结论：本数据集不能用本次实验检验图增强；2009 的「无增益」未被推翻也未被确认
- 禁止的结论：不能说「2012 再次证明无增益」；不能换成别的图仍称本协议复现
