# 实验方案对齐说明（v2 执行版）

> 依据《知识追踪项目推荐实验方案》整理，明确两条实验线、评估协议、数据埋点与可复现性要求。
> 执行顺序以方案 §推荐执行顺序为准，本文只记录已落地与待落地事项。

## 1. 两条实验线（已确立）

| 实验线 | 数据 | 用途 |
|---|---|---|
| 模型比较 | 公开数据集（ASSISTments 2009 → Junyi/2012 → XES3G5M） | Majority → Rule → BKT → DKT → GCN-DKT 正式对比 |
| 网站应用案例 | 网站真实答题数据 | 展示数据流程、掌握度计算、推荐与个案变化；样本小时称「案例/探索性分析」 |
| （辅助）模拟数据 | `backend/models/simulator.js` 合成 | 仅接口联调、闭环演示、边界测试；**不参与效果评价，不写进结论** |

## 2. 评估协议（已落地于 `backend/models/baselineEval.js`）

- 任务：时间顺序预测下一次答题结果（walk-forward，禁止使用目标时刻之后的记录）；
- 必报指标：AUC、LogLoss、Accuracy、F1 + 预测样本数、学生数、题目数、知识点数、数据时间范围
  （`datasetStats()` 自动输出，结果 JSON 内含 `dataset` 与 `evalProtocol` 字段）；
- **学生级 bootstrap**：重采样单位为学生（同一学生的记录彼此相关，整组有放回抽取），
  约 1000 次，取 2.5%/97.5% 分位数；`--bootstrap N` 可调；
- **配对比较**：相同学生、相同测试样本，池化指标差 + 学生级 bootstrap CI 与双侧 p 值；
  禁用「学生内逐行 AUC 均值」（短序列上有机械性负偏差，会产生伪显著，详见
  `现有掌握度公式提取与规则基线.md` §6）；
- 可复现：结果 JSON 记录数据源、数据集统计、评估协议、bootstrap 次数、随机种子与全部超参数。

## 3. 持久化与埋点（已落地）

答题记录 `student_answer` 字段：

```text
userId（student_id）, questionId, kpCode（knowledge_point_id）,
isCorrect, costTime / answerDuration（answer_duration）, attemptIndex（attempt_index）,
userAnswer, sourceRef, createdAt
```

推荐日志 `recommendationLogs` 字段（`personalized-push.js` 写入）：

```text
recommendationSource, algorithm, modelVersion, recommendedAt, answeredAt,
details[]: { questionId, recommendationSource, recommendationReason,
             algorithm, modelVersion, masteryBefore,
             estimatedCorrectProbability, probabilitySource, questionDifficulty }
```

`estimatedCorrectProbability` 为展示掌握度启发式估计（`probabilitySource:
display-mastery-heuristic`），不是 BKT/DKT 模型输出。

`answeredAt` 由 `learning.js synchronize()` 在学生作答后自动回填（只回填一次）。

真实/模拟数据隔离：模拟记录统一带 `source: "simulated"`，学生档案前缀 `stu-sim-`
（教师端显示为「模拟-高水平-XX」等），可按标记识别和清理。

## 4. 模拟用户四类原型（已落地于 `simulator.js`）

| 原型 | 占比 | 画像要点 |
|---|---|---|
| 高水平 | 20% | 能力 0.8±0.06，遗忘慢，猜测/失误少 |
| 普通 | 40% | 能力 0.55±0.08，标准参数 |
| 薄弱 | 25% | 能力 0.3±0.07，练得多，正确率低 |
| 突击型 | 15% | 起点低、0.2~2 天间隔集中练、增益 0.09 但遗忘 0.06（快学快忘） |

用法：`node models/simulator.js --students 30 --kp 8 --seed 7 [--inject]`

## 5. 研究进度表述（对外口径，2026-10-29 更新：已接入 ASSISTments 2009）

**当前可以说：**

> 当前版本完成了规则掌握度基线（含线上公式复现 Online-Rule 与 Rule-0/1/2）及其时间顺序
> 评估框架（学生级 Bootstrap 统计），并完成了网站侧基于掌握度、先修关系和复习间隔的
> 规则推荐闭环。**已在 ASSISTments 2009-2010 公开数据集上完成数据接入、统一格式转换、
> 清洗记录与规则基线复现**（266,948 条交互 / 3,931 名学生 / 100 个知识点，
> Rule-0 AUC 0.704，显著优于 Majority 0.539）。BKT、DKT 与图增强知识追踪仍属后续计划。

**当前不宜说：**

- 已完成 BKT / DKT / GCN-DKT（尚未实现）；
- 已完成公开教育数据集上的完整模型对比实验（目前只有规则基线，BKT/DKT 未实现）；
- 已证明知识图谱显著提升预测效果（未验证）；
- 已证明推荐策略提升学生学习成绩（未验证）；
- 已完成教育大模型研究（未开始）。

**模拟数据定位：** Rule-0 在模拟数据上的优势只说明评估管道能识别模拟器中的规律，
属于「模拟数据管道回归测试」，不能证明真实教育数据上的效果。模拟数据一律带
`source=simulated` 标记，与真实数据分开统计。

**线上推荐的实际逻辑：** `personalized-push.js` 当前是「先选低掌握度知识点、再选较
容易题目」的规则推荐；日志中的 `estimatedCorrectProbability` 是展示掌握度 ÷ 100 的
启发式估计（`probabilitySource: display-mastery-heuristic`），**不是** BKT/DKT 模型
输出。接入知识追踪模型后再使用真实模型概率。两套推荐逻辑已用 `algorithm` 字段区分：
`rule-based-push`（线上规则推荐）与 `hybrid-experimental`（实验性综合推荐）。
