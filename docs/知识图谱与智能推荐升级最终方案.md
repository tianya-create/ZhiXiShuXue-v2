# 基于知识图谱增强知识追踪的个性化数学练习推荐系统

## 1. 项目总体目标

将现有的“知识图谱”和“智能推荐”从规则展示与规则打分，升级为一个可验证的教育智能系统：

```text
数学知识图谱
      ↓
知识点表示学习
      ↓
学生动态知识追踪
      ↓
学生知识状态估计
      ↓
个性化练习推荐
      ↓
教育大模型生成解释性反馈
```

项目的核心研究问题可以定义为：

> 在数学知识点先修关系的帮助下，图增强知识追踪模型是否比传统规则掌握度、BKT 和普通 DKT 更准确地预测学生下一次答题结果，并改善个性化练习推荐效果？

## 3. 知识图谱设计

### 3.1 节点类型

建议至少包含两类节点：

```text
知识点节点
题目节点
```

后续可以扩展：

```text
章节节点
教材节点
错题节点
```

### 3.2 边类型

```text
知识点 A ──先修关系──> 知识点 B
题目 Q ──考查关系──> 知识点 K
知识点 A ──相似关系──> 知识点 B
题目 Q1 ──相似题──> 题目 Q2
```

### 3.3 学生行为数据

学生行为不一定直接作为静态图中的节点，也可以作为动态交互记录：

```text
学生 S
  └── 在时间 t
        └── 作答题目 Q
              ├── 答对或答错
              ├── 用时
              └── 对应知识点 K
```

### 3.4 推荐的数据表

```text
students
- student_id
- name

knowledge_points
- knowledge_point_id
- name
- chapter
- prerequisite_ids

questions
- question_id
- content
- difficulty
- answer
- explanation

question_knowledge
- question_id
- knowledge_point_id

answer_records
- record_id
- student_id
- question_id
- knowledge_point_id
- is_correct
- answer_time
- duration
- created_at
```

## 4. 知识追踪模型路线

### 4.1 规则掌握度 baseline

先保留现有规则作为基线：

```text
掌握度 = 最近正确率
       + 连续答对奖励
       - 连续答错惩罚
       - 时间遗忘惩罚
```

规则模型必须明确：

- 输入是什么；
- 输出是什么；
- 参数是多少；
- 如何处理冷启动；
- 如何按照时间顺序评估；
- 使用哪些指标。

建议形成三个版本：

```text
Rule-0：最近正确率
Rule-1：正确率 + 连续答题修正
Rule-2：正确率 + 连续答题修正 + 时间衰减
```

### 4.2 BKT

Bayesian Knowledge Tracing 将学生对知识点的掌握状态看作隐藏变量，根据学生每次答题结果更新掌握概率。

每个知识点可以设置：

- `P(L0)`：初始掌握概率；
- `P(T)`：学习转移概率；
- `P(G)`：猜对概率；
- `P(S)`：失误概率。

BKT 的优点：

- 数据量要求较低；
- 解释性强；
- 容易与现有系统结合；
- 适合做第一个教育建模模型。

### 4.3 DKT

Deep Knowledge Tracing 使用 RNN、LSTM 或 GRU 建模学生答题序列，预测下一道题是否答对。

输入示例：

```text
Q1-正确，Q3-错误，Q5-正确，Q2-错误
```

输出：

```text
学生下一次遇到某道题时的答对概率
```

基本结构：

```text
题目和答题结果 embedding
          ↓
        LSTM / GRU
          ↓
   学生动态知识状态 h_t
          ↓
预测下一题答对概率
```

### 4.4 图增强知识追踪

这是最适合项目升级的研究模型。

基本结构：

```text
知识图谱
   ↓
GCN / GAT
   ↓
知识点向量

学生答题序列
   ↓
LSTM / GRU
   ↓
学生动态状态

学生状态 + 题目向量 + 知识点向量
   ↓
MLP
   ↓
下一题答对概率
```

建议先实现简单版本：

1. 使用 PyTorch Geometric 构建知识点图；
2. 使用 GCN 生成知识点 embedding；
3. 使用 GRU 建模学生答题序列；
4. 拼接学生状态、题目向量和知识点向量；
5. 使用 MLP 输出答对概率。

不要一开始就实现复杂的 Transformer 或多层异构图网络。先完成可运行、可解释、可比较的 GCN-GRU 版本。

## 5. 个性化练习推荐设计

### 5.1 两阶段推荐架构

推荐系统建议拆成两个阶段：

```text
候选题生成
      ↓
候选题排序
      ↓
返回 Top-K 题目
```

### 5.2 候选题生成

根据学生当前知识状态筛选 20～50 道候选题：

- 包含学生薄弱知识点；
- 难度接近学生当前能力；
- 不是近期重复练习的题目；
- 满足知识点先修关系；
- 题目状态正常且有答案解析。

### 5.3 候选题排序

可设计如下评分函数：

```text
score(q) =
    α × 学习收益
  + β × 题目适配度
  + γ × 遗忘风险
  + δ × 难度匹配度
  - λ × 重复惩罚
```

其中：

```text
学习收益 = 预计做题后掌握度提升
```

初版可以使用规则估计：

```text
gain(q) =
    薄弱程度
  × 知识点重要程度
  × 题目适配度
```

后续可以使用知识追踪模型估计学生做题前后的状态差异。

### 5.4 推荐解释

系统应该告诉学生“为什么推荐这道题”，例如：

```text
推荐原因：
- 你最近在“二次函数图像”知识点上的正确率为 42%；
- 已连续 6 天未练习该知识点；
- 本题难度与当前预测能力匹配；
- 本题可以帮助巩固“顶点坐标”相关概念。
```

推荐解释是系统可用性和面试展示效果的重要部分。

## 6. 教育大模型的接入方式

不建议训练一个新的教育大模型。更适合的路线是：

> 知识追踪模型负责判断学生状态，教育大模型负责解释、问答和生成学习建议。

系统结构：

```text
学生答题记录
      ↓
BKT / DKT / GCN-DKT
      ↓
知识点掌握状态
      ↓
检索相关知识点、例题、错题和解析
      ↓
大模型生成讲解和学习计划
```

### 6.1 大模型适合承担的功能

- 错题原因解释；
- 知识点讲解；
- 分步骤提示；
- 个性化学习计划；
- 相似题生成；
- 学习情况总结；
- 教师端学情报告生成。

### 6.2 Graph-RAG 反馈流程

学生提问：

```text
我为什么总做错一元二次方程的判别式？
```

系统先提取结构化状态：

```json
{
  "weak_knowledge": ["判别式", "一元二次方程"],
  "mastery": {
    "判别式": 0.32,
    "因式分解": 0.74
  },
  "recent_errors": ["题目102", "题目118"]
}
```

然后检索相关知识点、教材内容和错题，把结果交给大模型：

```text
你是一名数学教师。
学生薄弱知识点：判别式。
当前掌握度：0.32。
最近错题：题目102、题目118。
请先解释可能的错误原因，再给出一道基础题和一道迁移题。
不要直接泄露答案。
```

这样，大模型输出会受到学生知识状态和知识图谱约束，而不是普通聊天机器人。

### 6.3 大模型评价指标

可以从以下方面进行人工或半自动评价：

- 事实正确性；
- 是否命中学生薄弱知识点；
- 解释是否完整；
- 是否存在错误引导；
- 是否直接泄露答案；
- 教师评分；
- 学生满意度。



### 7.4 实验指标

#### 答题预测

- AUC；
- Accuracy；
- LogLoss；
- F1；
- Brier Score。

#### 推荐效果

- 推荐题目后的下一次正确率；
- 推荐前后知识点掌握度变化；
- 薄弱知识点覆盖率；
- 推荐重复率；
- 题目难度匹配程度；
- 推荐完成率。

#### 大模型效果

- 教师人工评分；
- 知识点命中率；
- 事实错误率；
- 答案泄露率；
- 学生反馈评分。

## 8. 数据量与模型选择

| 数据情况 | 推荐方案 |
|---|---|
| 少于 1000 条答题记录 | 规则法、BKT、IRT |
| 1000～10000 条 | DKT、GRU-DKT、简单推荐排序 |
| 10000 条以上 | GCN-DKT、Transformer KT |
| 有持续用户交互 | Contextual Bandit、在线推荐实验 |
| 有教材和题目解析 | Graph-RAG 教育大模型 |

如果真实用户数据较少，可以先使用公开教育数据集验证模型，再把自己系统的数据作为案例分析。

不要在小数据上直接训练复杂 Transformer，也不要把模拟数据结果包装成真实学习效果。

## 9. 最推荐的落地顺序

### 第一步：整理当前规则

- 从现有代码中提取掌握度公式；
- 形成 Rule-0、Rule-1、Rule-2；
- 实现时间顺序评估；
- 输出 AUC 和 LogLoss。

### 第二步：实现 BKT

- 为每个知识点估计掌握概率；
- 与规则模型比较；
- 分析不同知识点和不同学生群体的差异。

### 第三步：实现 DKT

- 使用 GRU 或 LSTM 建模答题序列；
- 预测下一题答对概率；
- 与 BKT 比较效果。

### 第四步：加入知识图谱

- 整理知识点先修关系；
- 使用 GCN 生成知识点向量；
- 将图向量接入 GRU-DKT；
- 比较 DKT 和 GCN-GRU DKT。

### 第五步：升级推荐系统

- 先生成候选题；
- 使用模型预测学生答对概率；
- 按学习收益和难度匹配排序；
- 展示推荐原因。

### 第六步：接入教育大模型

- 先实现知识点检索；
- 再加入学生掌握度和错题信息；
- 最后实现 Graph-RAG 解释和学习计划；
- 对输出进行人工评价。

## 10. 项目最终可以这样描述

> 本项目面向数学学习场景，构建了由知识点、题目和先修关系组成的教育知识图谱。首先使用规则掌握度、BKT 和 DKT 对学生知识状态进行建模，然后将知识图谱通过 GCN 编码为知识点表示，并结合 GRU 建模学生答题序列，预测学生下一次答题结果。在此基础上，系统根据学生预测掌握度、题目难度、遗忘风险和知识点先修关系生成个性化练习。教育大模型不直接负责学生状态判断，而是基于知识追踪结果和知识图谱检索内容生成错题解释、学习提示和个性化学习计划。

这段描述比“使用知识图谱和智能推荐”更准确，也更适合保研面试、项目答辩和科研材料。

## 11. 最小可行版本

如果时间有限，优先完成：

```text
规则掌握度 baseline
      ↓
BKT
      ↓
GRU-DKT
      ↓
基于预测掌握度的题目排序
      ↓
知识状态增强的 RAG 解释
```

图神经网络可以作为后续增强版本，不必一开始就实现全部功能。

最小可行版本已经能够形成完整闭环：

```text
答题记录
  ↓
学生知识状态估计
  ↓
下一题答题预测
  ↓
个性化推荐
  ↓
错题解释和学习反馈
```
