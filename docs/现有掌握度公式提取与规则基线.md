# 现有掌握度公式提取与规则基线实现

> 对应《知识图谱与智能推荐升级最终方案》第一步：整理当前规则，形成 Rule-0 / Rule-1 / Rule-2，实现时间顺序评估，输出 AUC 和 LogLoss。

## 1. 系统原有掌握度公式（提取自 `backend/services/masteryEngine.js`）

原系统对每个（学生, 知识点）计算：

```text
输入：该知识点的全部答题记录（按时间升序），取最近 10 次
1. correctRate = 最近10次答对数 / 最近10次总数
2. mastery = round(correctRate × 100)          # 百分制
3. 连对修正：最近 3 次全对，且最近3次平均用时 ≤ 历史平均用时 × 1.2
   → mastery = min(100, mastery + 10)
4. 连错修正：最近 2 次全错
   → mastery = max(0, mastery - 10)
5. 样本不足（次数 < 5 或去重题目 < 3）→ mastery 封顶 79，状态标记「样本不足」
6. 状态划分：≥80 已掌握，≥60 待巩固，<60 薄弱
```

原系统**没有时间衰减**；`backend/services/recommendation.js` 中的「遗忘紧迫度」
（`getForgettingUrgency`，按距上次练习天数与复习间隔 [1,3,7,14] 的距离打分）
只用于推荐排序，不属于掌握度计算。

## 2. 四个规则基线版本

新模块：`backend/models/ruleMastery.js`（公式独立成文件，不散落在接口代码中）。
参数固定在 `backend/models/baselineParams.json`，禁止按学生调参。

| 模型 | 公式（[0,1] 概率口径） | 来源 |
|---|---|---|
| Online-Rule | 窗口 10 **普通正确率（无平滑）** + 连对3次且速度达标 `+0.10` + 连错2次 `-0.10`；样本不足封顶 `0.79` | **核心计算逻辑复现线上公式**，输出经概率裁剪 [0.01, 0.99] 以适配概率指标（非逐字节复现） |
| Rule-0 | `(答对数 + 1) / (次数 + 2)`（拉普拉斯平滑，窗口 10） | 简化基线 |
| Rule-1 | Rule-0 + 连对3次且速度达标 `+0.10` + 连错2次 `-0.10`；样本不足封顶 `0.79` | 受线上公式启发；**注意使用平滑正确率，并非线上公式的完全复现** |
| Rule-2 | Rule-1 × `exp(-0.03 × d)`，d 为距上次练习天数 | 新增消融版本 |

> 表述注意：Rule-1 与线上公式的差异在于拉普拉斯平滑。衡量「线上公式本身」用
> Online-Rule；Rule-1 是平滑化的改进版本。二者已在评估中并列对比。

统一细节：

- 冷启动：无历史 → `0.5`；
- 概率输出裁剪到 `[0.01, 0.99]`，避免 0/1 极端值导致 LogLoss 爆炸；
- `predictNextCorrect(model, records, { now })` 统一入口，输出即下一题答对概率 p。

## 3. 时间顺序评估（防数据泄漏）

实现：`backend/models/baselineEval.js`。

- 对每个（学生, 知识点）按时间升序遍历，**预测第 t 次只使用第 1 ~ t-1 次记录**；
- Rule-2 的预测时刻取目标答题时刻，时间衰减按真实练习间隔计算；
- Majority 基线使用全局时间前缀的累积正例率（拉普拉斯平滑）：实现为
  **全局时间排序的前缀和 + 二分查找**，取「严格早于预测时刻」的记录统计，
  与组处理顺序完全无关（已加交错时间无泄漏回归测试）；
- 指标（零依赖实现）：AUC（并列秩修正）、LogLoss、Brier、Accuracy、F1（阈值 0.5）。

运行方式：

```bash
cd backend
node models/baselineEval.js --source synthetic                 # 合成数据验证管道
node models/baselineEval.js --source db                        # 内存数据库真实答题记录
node models/baselineEval.js --source csv --file records.csv    # 外部数据
# CSV 列：userId,kpCode,questionId,isCorrect,costTime,createdAt
```

结果 JSON 默认写入脚本所在项目的 `实验结果文件/baseline-results-<source>.json`；可用 `--out <目录>` 指定其他
输出目录（不存在时自动创建）：

```bash
cd backend
node models/baselineEval.js --source synthetic                 # 合成数据验证管道
node models/baselineEval.js --source db                        # 数据库真实答题记录
node models/baselineEval.js --source csv --file records.csv --bootstrap 2000 --out ../实验结果文件
# CSV 列：userId,kpCode,questionId,isCorrect,costTime,createdAt（attemptIndex 可选）
```

**时间戳处理规则**：同一时间戳视为同一答题批次，批次内记录互不为历史信息（历史只含
严格早于目标时刻的记录）；排序以 createdAt、attemptIndex、原始行序为稳定次序，
原始 CSV 行顺序变化不改变评估结果（有回归测试）。

## 4. 指标解读（如何正确比较模型）

| 指标 | 衡量 | 使用注意 |
|---|---|---|
| AUC | 排序能力 | 主要比较指标 |
| LogLoss | 概率预测质量 | 对极端/过度自信概率敏感 |
| Brier | 概率校准与误差 | 与 LogLoss 互补 |
| Accuracy / F1 | 固定阈值 0.5 下的分类表现 | **不宜单独作为模型排名依据** |

注意事项（结果 JSON `evalProtocol.metricInterpretation` 同步记录）：

- **不能只凭 Accuracy 宣称某模型最优**：可能出现 Rule-2 的 Accuracy 较高、
  但 Rule-0 的 LogLoss 和 Brier 更好的情况——排序能力与概率质量是两个维度；
- **Majority 的 F1 可能为 0**：其预测是全局正例率，当正例率 < 0.5 时固定阈值
  0.5 下全部预测为负类。这不是实现错误，但 F1 对 Majority 解释力有限，主要比较
  AUC / LogLoss / Brier；
- **Online-Rule 的 LogLoss 偏高是预期现象**：无平滑的普通正确率在极端区间
  （连续对/错）输出接近 0/1 的概率，虽被裁剪到 [0.01, 0.99]，概率校准仍差——
  这说明它有排序能力但概率质量不足，结果 JSON 中的分箱校准表（`calibration` 字段）
  可直接查看各概率区间的预测均值 vs 实际正确率；
- 页面展示的掌握度分数（0-100，样本不足封顶 79）是**展示规则，不是校准概率**，
  与实验中的预测概率分属两套口径。

## 5. 合成数据管道验证结果（不可作为真实结论）

数据：40 名学生 × 6 个知识点合成数据，2688 个预测样本（bootstrap 2000 次）。

| 模型 | AUC | LogLoss | Brier | Accuracy | F1 |
|---|---:|---:|---:|---:|---:|
| Majority | 0.5326 | 0.6885 | 0.2477 | 0.5487 | 0.6953 |
| Online-Rule | 0.6853 | 0.8048 | 0.2475 | 0.6469 | 0.6904 |
| Rule-0 | 0.6888 | 0.6374 | 0.2233 | 0.6455 | 0.6935 |
| Rule-1 | 0.6912 | 0.6633 | 0.2286 | 0.6440 | 0.6872 |
| Rule-2 | 0.6907 | 0.6722 | 0.2329 | 0.6265 | 0.6309 |

管道行为符合预期：Majority AUC≈0.5，规则模型明显优于猜测；Online-Rule AUC 接近
Rule 家族但 LogLoss 明显更差（无平滑导致概率校准差，见 §4）。合成数据不含遗忘机制，
Rule-2 与 Rule-0 差异微小属预期现象；真实数据上的结论以 `--source db/csv` 的运行为准。

## 7. 统计严谨性（bootstrap 置信区间与配对检验）

小数据下模型间 AUC 差 0.01~0.03 可能纯属随机波动，因此评估器内置：

- **学生级（聚类）bootstrap 置信区间**：以学生为重采样单位（保留其全部记录，学生内相关性不被拆散），
  报告 AUC / LogLoss 的 95% CI；
- **配对显著性检验**：两模型 walk-forward 输出按预测时刻对齐后，在学生级 bootstrap 下
  计算**池化** ΔAUC / ΔLogLoss 的置信区间与双侧 p 值。

```bash
cd backend
node models/baselineEval.js --source csv --file 实验结果文件/simulated-records.csv --bootstrap 2000
```

**p 值使用规范**：bootstrap 次数有限时 p 值分辨率低（如 50 次重复时多个 p 值可能同为
0.0392），**p 值是探索性指标，不作为模型优越性的充分依据**。正式结果至少 2000 次
bootstrap（最好 5000 次）；主要结论基于 Δ 及其 95% CI（CI 不含 0 → 差异方向稳定），
并做随机种子稳定性检查（已验证 seed 42 与 2027 下结论一致）。

方法说明（重要）：池化 AUC 是 KT 领域标准指标；**组内逐行 AUC 的均值不可用作对比统计量**——
短序列上增长窗口预测器存在机械性负偏差（pred(t) 的历史窗口包含 target(t-1)，相邻行的
正例预测值反而更低），会把随机差异放大成「显著」。已用 i.i.d. 对照数据回归测试防止复发。

## 8. 模拟用户生成器（`backend/models/simulator.js`）

用途：填充网站演示数据、验证推荐与学情闭环、压力测试评估管道。
**红线：模拟数据的评估结果严禁写进报告或论文。**

行为模型：学生能力 θ~N(0.55,0.15)；知识点个人偏好 ±0.12；练习增益 0.045×(1-掌握度)；
场次间隔 1~10 天遗忘 exp(-0.02d)；猜测 0.15 / 失误 0.08；用时与正误和能力相关。

```bash
node models/simulator.js --students 30 --kp 8 --seed 7            # 仅生成 CSV
node models/simulator.js --students 30 --kp 8 --seed 7 --inject   # 写入网站数据库
```

- 注入的记录带 `source: "simulated"` 标记，学生档案前缀 `stu-sim-`，可识别、可清理；
- 已注入 30 名虚拟学生共 1865 条答题记录（seed=7），掌握度引擎可正常消费
  （样例：alg-1 掌握度 60「待巩固」confidence=sufficient）；
- 数据落在 `backend/database/questions.sqlite`，服务重启不丢。

## 9. 模拟数据上的完整评估示例（仅验证管道，非真实结论）

60 名虚拟学生、3602 条记录、3284 个预测样本、学生级 bootstrap × 500：

| 模型 | AUC [95% CI] | LogLoss [95% CI] |
|---|---|---|
| Majority | 0.4915 [0.4676, 0.5165] | 0.6671 [0.6577, 0.6770] |
| Rule-0 | 0.5892 [0.5630, 0.6116] | 0.6931 [0.6781, 0.7074] |
| Rule-1 | 0.5874 [0.5611, 0.6095] | 0.7245 [0.7077, 0.7405] |
| Rule-2 | 0.5876 [0.5623, 0.6100] | 0.7162 [0.6989, 0.7324] |

配对检验：Majority vs Rule-0 ΔAUC = -0.098 [-0.128, -0.065]，p=0.004（规则模型显著优于猜测）；
Rule-0/1/2 两两之间 AUC 差异均不显著（CI 含 0）——该模拟器的掌握度动力学较平滑，
连对/时间衰减修正无额外增益，属预期现象，不外推到真实数据。
