# 图增益闸门实验：先修信息探针（Prior-Signal Probe）

编写日期：2026-11-09 ｜ 前置：阶段 E 五种子聚合 + 分层误差分析（`stratified-error-analysis.json`）

定位：**决策实验**，不是论文实验。目的是用一周时间、零 GNN 训练，判定 "先修信息" 是否存在于 Full-DKT 的残差中，从而决定知识追踪这条线继续还是终止。



***

## 0. 一句话结论先行

分层分析已经证明：在 "共现图 + ASSIST2009" 这个构造上，无论怎么调参都不会出现可检出的增益。原因不是运气，是三条硬约束：



1. **结构上限**。46% 的目标落在孤立节点（度 0），22% 落在 hub（度 ≥3）。AUC 是成对比较，两端都在 hub 上的比较对只占 22%² ≈ 4.8%，至少一端是 hub 的占 1−0.78² ≈ 39%。要让整体 ΔAUC 达到冻结阈值 +2e-3，hub 子群得做到约 +5e-3—— 是实测 hub 值（−0.43e-3）的 12 倍。这个实验的分辨率被图的覆盖率锁死了。

2. **信息论冗余**。共现边来自 "同一学生先后做过这两道题"，这个统计可以从作答序列本身还原，而 GRU 已经吃下完整序列。共现图对模型是零增量信息，换数据集不改变这个性质。

3. **覆盖率只是必要条件**。把 100 个节点全连上，只要边还是共现语义，结果不会变。真正稀缺的是**序列之外的信息**：教材章序、课标要求、教学法上的先修约束。

所以唯一有信息论依据的下一步，是把**图的信息来源**从共现换成先修。但在投入三个月重做之前，先用本方案花一周验证一件事：**先修关系到底有没有模型没吃到的信息量**。没有就立刻转向，不要再赌。



***

## 1. 本方案要回答的问题

> 在 Full-DKT 已经充分吸收作答序列之后，知识点先修关系是否还能对目标正确率提供增量预测力？

注意问题的措辞：不是 "先修图能不能提升 KT 模型"，而是 "**先修信息是否存在于残差中**"。前者要训模型，后者只要训一个逻辑回归。如果残差里根本没有先修信息的痕迹，那么任何图模型都不可能把它挖出来 —— 这是本方案的核心逻辑。



***

## 2. 前置产物：先修边怎么来

### 2.1 输入清单



* `backend/datasets/assist2009/skill-names.json`：111 条 `{id: "名称"}`（含清洗后无交互的 11 条）

* `backend/实验结果文件/gcn-dkt-v1/seed-42/vocabulary.json`：`kpList`，100 个 KC，`a09-s{id}` 形式。**已验证 seed 42–46 的 kpList 完全相同**，因此先修图只需建一份索引。

* 名称映射规则：`kpCode = "a09-sN"` ↔ `skill-names.json["N"]`。只保留出现在 kpList 里的 100 个，其余 11 个不参与。

### 2.2 LLM 抽取协议

角色设为 "初中数学教研员"。输入是 100 条 `知识点名称`（**只给名称，不给 id，避免模型按数字排序编造关系**）。

要求模型输出有向边 `a → b`，语义为 "掌握 b 之前应先掌握 a"，每条附 `reason`（≤25 字）与 `confidence`（1–3）。

约束写进 prompt：



* 只允许使用清单内的名称，逐字匹配，不得新增或改写；

* 不允许自环；

* 每条边的 `b` 至多 2 个先修，全局出度 ≤3；

* 若两个知识点确实无先修关系，就不要输出；

* 只输出 CSV，列为 `sourceKp,targetKp,confidence,reason`。

**跑 3 次**（换措辞、换 temperature，例如 0 / 0.7 / 1.0），取 ≥2/3 次一致出现的边作为候选。这一步的意义是压掉单次生成的随机噪声。

### 2.3 规则校验（脚本自动，全部通过才继续）



1. **白名单**：每个名字必须能在 kpList 里逐字找到，否则丢弃；

2. **无环**：拓扑排序检测。若有环，按 `confidence` 从低到高删边直到无环，删掉的边记录在案；

3. **度数上限**：出度 ≤3、入度 ≤2；

4. **边数区间**：40–120 条（与共现图 42 条同量级，保证 A/B 两组可比；少于 40 条说明抽取质量不足，多于 120 条说明模型在滥连）；

5. **孤立节点比例记录**：算清这版先修图覆盖多少 KC、多少 KC 仍孤立 —— 这个数字后面要和目标覆盖率一起报。

### 2.4 人工核验（不可跳过）

抽 80 条边核验：40 条候选边 + 40 条 "高置信但被规则否决" 的边（后者用来检验规则是否误杀）。



* 你自己按教材目录 / 课标独立判对错，报 **precision**；

* 再找一位同学或数学老师独立标其中 50 条，与你比对，报 **Cohen's κ**；

* 通过线：**precision ≥ 0.75 且 κ ≥ 0.60**。不达标就改一次 prompt 重跑；仍不达标则判定 "该数据集的先修关系不适合 LLM 抽取"，直接跳到第 5 节决策矩阵的 "终止" 分支。

### 2.5 落盘

`backend/datasets/assist2009/prior-edges.csv`



```
sourceKp,targetKp,confidence,votes,reason
a09-s50,a09-s54,3,3,"先会比较分数大小，才能做小数排序"
```

索引不写进这个文件：由探针脚本按 `vocabulary.json` 的 kpList 顺序换算成 `sourceIndex / targetIndex`，与 `graph-real-edges.csv` 的索引体系保持一致。**边文件定稿后立刻 git commit，并记录 sha256**—— 这是防止 "看到结果再改图" 的唯一手段。

## 3. 探针实验设计

### 3.1 数据与划分



* 目标集：`seed-{42..46}/targets.json` 的 `targets` 数组，每种子 36,967 条（seed 45 为 30,832）

* 预测：同目录 `predictions.jsonl`，每行含 `targetKey / userId / kpCode / createdAt / target / preds`，取 `preds["Full-DKT"]`

* 交互：`backend/datasets/assist2009/interactions.csv`（`userId, questionId, kpCode, isCorrect, costTime, createdAt, sequenceIndex`）

* 训练学生名单：`split.json` 的 `train` 数组（2,752 人），只用于计算 `kc_train_acc` 这一项全局统计

* 交叉拟合：**按 userId 做 5 折 GroupKFold**（589 个 test 学生，学生不跨折），折内 fit、折外 predict，汇总成 OOF 预测

### 3.2 特征块

所有特征严格使用 `createdAt < t` 的交互，任何用到 t 及之后的实现都视为 bug。

**基底块 S（10 项）**



| 特征                 | 定义                                      |
| ------------------ | --------------------------------------- |
| `dkt_logit`        | `logit(clip(p_Full-DKT, 1e-6, 1-1e-6))` |
| `kc_attempts_log`  | 该 KC 在 t 前作答次数，log1p                    |
| `kc_last5_acc`     | 该 KC 最近 5 次正确率；无则缺失                     |
| `kc_last_correct`  | 该 KC 最近一次对错（0/1）；无则缺失                   |
| `kc_gap_log`       | 距该 KC 上次作答的分钟数，log1p；无则缺失               |
| `kc_train_acc`     | 该 KC 在训练学生全体交互上的正确率                     |
| `stu_attempts_log` | 学生 t 前总作答数，log1p                        |
| `stu_acc`          | 学生 t 前全局正确率                             |
| `stu_last5_acc`    | 学生最近 5 次正确率                             |
| `hist_len_log`     | `sequenceIndex − 1`，log1p（即分层分析里的历史长度）  |

`dkt_logit` 放进基底是这套设计的关键：基底已经等价于 "Full-DKT 的水平"，因此 Δ 衡量的是**残差中的增量**，而不是 "先修能否改进一个弱线性模型"。后者会给出虚高的数字，且不可迁移到强模型。

**邻居块（6 项，A/B/C 三组同构造）**

设邻居集 `N(k)`，`m = |N(k)|`：



| 特征                | 定义                                                                       |
| ----------------- | ------------------------------------------------------------------------ |
| `nb_missing`      | `m = 0` 或 t 前无任何邻居作答 → 1                                                 |
| `nb_cov`          | N 中被练过的比例（有 ≥1 次 t 前作答）                                                  |
| `nb_recent_acc`   | 各被练过邻居 "最近 5 次正确率" 的加权平均，权重 = 边权重（先修用 confidence，共现用 support，随机用 1）；权重归一 |
| `nb_last_correct` | 学生最近一次落在 N 上的作答对错                                                        |
| `nb_gap_log`      | 距最近一次落在 N 上作答的分钟数，log1p                                                  |
| `nb_recent20`     | 学生最近 20 次作答中落在 N 的次数（0–20）                                               |

`nb_attempts_log`（N 上累计作答次数）可选，若要加入必须在跑第一遍之前决定并写进 config，不许事后加。

**三组邻居定义**



| 组        | 边集                                | 方向处理                                  |
| -------- | --------------------------------- | ------------------------------------- |
| **A 先修** | `prior-edges.csv`                 | 有向：`N(k) = {a : (a,k) ∈ E}`           |
| **B 共现** | `seed-{s}/graph-real-edges.csv`   | 无向：`N(k) = {a:(a,k)∈E} ∪ {b:(k,b)∈E}` |
| **C 随机** | `seed-{s}/graph-random-edges.csv` | 无向，度数分布与 B 匹配                         |

C 组是**噪声地板**。任何 A 组 "增益" 若不能明显超过 C，就不是结构证据。

### 3.3 模型



* 主：L2 逻辑回归（`C = 1.0`），StandardScaler，缺失值标准化后补 0，另加缺失指示变量

* 复核：`HistGradientBoostingClassifier(max_iter=200)`，仅用于验证符号一致，不作主判定

* 五个特征集，各自独立拟合：`S`、`S+A`、`S+B`、`S+C`、`S+A+B`

* 全部使用同一折划分、同一随机种子、同一次运行

### 3.4 指标

每种子报：



* `LL(S)`、`LL(S+A)`、`LL(S+B)`、`LL(S+C)`、`LL(S+A+B)`（OOF LogLoss）

* `ΔA = LL(S) − LL(S+A)`，`ΔB`、`ΔC` 同理（正 = 有增益）

* `ΔA|B = LL(S+B) − LL(S+A+B)`：在已有共现信息之上，先修还能不能加分

* `coverage = 有先修邻居（m≥1）的目标数 / 全部目标数`，以及按 KC 计的覆盖率

## 4. 预注册判定阈值

阈值不靠感觉，靠阶段 E 的实测噪声。`multiseed-summary.json` 里 GCN−Full 的配对差值分布是：



* ΔLogLoss：均值 +0.000137，**总体标准差 0.000943**

* ΔAUC：均值 −0.000742，**总体标准差 0.001047**

也就是说，在你这套实现下，任何配对差值的种子间波动约 **±1e-3**。据此定阈值：



| 判定      | 条件（全部满足才算）                                                                       |
| ------- | -------------------------------------------------------------------------------- |
| **强信号** | `ΔA_mean ≥ 0.0020`（约 2σ）且 ≥4/5 种子为正 且 `ΔA_AB_mean ≥ 0.0010` 且 `ΔC_mean ≤ 0.0005` |
| **灰区**  | `0.0010 ≤ ΔA_mean < 0.0020`，或方向 ≥3/5 但幅度不足                                       |
| **无信号** | `ΔA_mean < 0.0010`，或 `ΔA − ΔB < 0.0005`                                          |

其中 `ΔA_AB_mean` 即第 3.4 节的 `ΔA|B`（在已有共现信息之上，先修的增量）。

补充护栏：若 `ΔC_mean ≥ 0.0010`（随机图也能带来 "增益"），说明特征构造有泄漏或分折有误，本次结果作废，先查 bug 再重跑。



***

## 5. 决策矩阵

信号强度 × 先修覆盖目标比例，决定三选一：



| 信号  | 覆盖率（有先修邻居的目标占比） | 结论                                                                     |
| --- | --------------- | ---------------------------------------------------------------------- |
| 强   | ≥ 40%           | **在本数据集建真先修图**，走路线 B：多数据集 + 强 baseline + 边置信度门控，3 个月可期                 |
| 强   | < 40%           | 先修信息存在但太稀疏，本数据集结题；**换数据集**（Junyi 或 ASSIST2012），先报图覆盖率与孤立节点比例再做图对照      |
| 灰区  | 任意              | 先扩到 ASSIST2012 复核一次，不直接投；不扩则按无信号处理                                     |
| 无信号 | 任意              | **终止 KT 线**。转教育资源构建（先修边 + 错误类型边的自动抽取与质量评估，投中文 CCF-C，无需 GPU），或回 SLAM 主线 |

我的预估：更可能落在 "强信号 + 覆盖不足" 或 "无信号" 两格。理由是 ASSIST2009 的 100 个知识点本身很碎（几何 + 统计的细粒度技能，如 `Box and Whisker`、`Interior Angles Triangle`、`Ordering Fractions`），先修关系天然稀疏，能连起来的对子有限。如果真是这样，说明这条线的瓶颈在**数据集的知识点粒度**，不在模型 —— 这本身也是一个可写进论文的结论。

## 6. 实现规范

### 6.1 文件



* 脚本：`backend/models/priorSignalProbe.js`（纯函数 + CLI，与 `stratifiedGraphErrorAnalysis.js` 同风格）

* 测试：`backend/test/priorSignalProbe.test.js`，≥14 项

* 输出：`实验结果文件/prior-probe-v1/probe.json`

* 配置：`实验结果文件/prior-probe-v1/probe-config.json`（冻结阈值、特征集、折数、随机种子、边文件 sha256）

### 6.2 CLI



```
cd backend
node models/priorSignalProbe.js \
  --input-dir 实验结果文件/gcn-dkt-v1 \
  --interactions datasets/assist2009/interactions.csv \
  --prior-edges datasets/assist2009/prior-edges.csv \
  --seeds 42,43,44,45,46 \
  --folds 5 \
  --out 实验结果文件/prior-probe-v1/probe.json
```

### 6.3 测试必须覆盖



1. **因果性**：给某个目标注入 t 之后的交互，特征输出不变（最容易出错的一条）

2. 缺失处理：`m = 0` 时六项全缺失且 `nb_missing = 1`

3. `nb_recent_acc` 权重归一：删掉一个邻居，均值仍在 \[0,1]

4. **先修方向**：把边反过来，`N(k)` 必须随之改变（有向性）

5. 共现图按无向处理：`(a,k)` 与 `(k,a)` 都应进 `N(k)`

6. GroupKFold 无泄漏：同一 `userId` 不同时出现在 fit 与 predict

7. OOF 覆盖率：五折预测条数之和 = 目标总数，`targetKey` 无重复

8. `log1p` 与 clip 边界（`p = 0` / `p = 1` 不产生 `Infinity`）

9. 索引换算：`kpCode → index` 与 `graph-nodes.json` 逐条一致

10. 单类目标（某折全正或全负）时的 AUC 返回 `null` 而不是报错

## 9. 结果怎么用

**若判为 build**：这份探针结果直接是论文 §5 的第一个表 ——"先修信息在 DKT 残差中的可检出增量"，它比 "我们训了个 GCN 有涨点" 更有说服力，因为它是机制证据而不是性能数字。

**若判为 stop**：这份探针 + 分层分析 + 阶段 E，三份合起来是一篇完整的负结果实证：图增强 KT 在稀疏共现图与细粒度知识点体系下的失效边界，含结构上限的算术证明。可投 EDM/AIED workshop 或中文期刊，不占 CCF 名额，但能给保研材料留下 "做过受控实证" 的记录，然后果断回 SLAM。

**若判为 switch-dataset**：说明瓶颈在知识点的粒度而非模型。下一步换 Junyi（KC 数量多、层级更清晰）或 ASSIST2012（265 个 KC），**第一件事是报图覆盖率与孤立节点比例**，覆盖率不到 40% 就不要做图对照 —— 这条规则是本次实验买来的，直接复用。
