# GRU-DKT 对照实验说明

> 对应《知识图谱与智能推荐升级最终方案》§9 第三步「DKT（GRU）」。
> **定位：深度知识追踪对照实验**——在与规则基线 / BKT 同一条数据管线上，
> 检验基础深度模型能否带来增益。不是复杂知识图谱模型，第一版刻意保持最小。

## 1. 模型（最小 DKT）

经典 DKT 输入方式（Piech et al. 2015）：

```
输入  interaction_id = 2 × kp_index + isCorrect
      （skill_1_correct = 1 / skill_1_wrong = 0 / skill_2_correct = 3 / ...）
结构  Embedding → GRU(1 层) → Linear → Sigmoid
输出  对「下一次作答的知识点 k」输出 P(答对) = σ(Wout[k]·h + bout[k])
      （等价于取经典 DKT 全知识点输出向量的第 k 维）
```

第一版超参（防过拟合配置，序列中位数 6 的数据不用大模型）：

| 项 | 值 |
|---|---|
| Embedding 维度 | 32 |
| GRU hidden size | 64 |
| GRU 层数 | 1（不用多层 GRU / Transformer / 图神经网络） |
| Dropout | 0.2（作用于 embedding 输出，仅训练时） |
| 学习率 | 1e-3（Adam，梯度全局范数裁剪 5.0） |
| Batch size | 64（序列为单位） |
| 最大 epoch | 50 |
| Early stopping | 验证集 LogLoss 连续 5 轮不下降 |
| 种子 | 42（初始化 / 洗牌 / dropout 各自独立随机流，全程可复现） |

变长序列处理：按学生组织序列，逐序列处理（无需 padding 截断）；
损失只在有效目标位（t ≥ 1）计算。实现：`backend/models/dkt.js`
（纯 JS：GRU 前向 + 完整 BPTT + Adam，参数量 31,524，无 Python/torch 依赖；
BPTT 经有限差分数值梯度抽查，相对误差 < 1e-3）。

## 2. 评估协议（学生级 train / validation / test）

**与 BKT 的「前 50% 估计段 / 后 50% 评估段」协议刻意不同**——DKT 需要独立
验证集做早停，直接复用 BKT 的前后半段协议会把验证信息泄进训练。
两种协议的结果**不混在一张表里、不直接互比**。

- 划分：**70% / 15% / 15% 学生**（按学生划分，固定种子 42；2752 / 590 / 589 名），
  同一学生的序列不会同时出现在训练与测试；
- 知识点词表只使用知识点 ID（构造 200 个交互 id 的嵌入查表），
  **不使用任何测试学生的作答标签或统计量**；参数训练仍仅使用 train 学生；
- DKT 在 train 学生上训练、validation 学生上早停、test 学生上评估；
- 对照模型在同一 test 学生目标集上逐条预测：
  - **BKT**：参数只在 train 学生上拟合（EM 全序列，100 个知识点：79 个容差收敛、
    11 个达迭代上限、10 个数据不足回退默认）；
  - **Rule-0 / Majority**：无参数，逐条 walk-forward；
- 目标集规则与规则基线完全一致：同一 (学生, 知识点) 组的首批次整体跳过，
  之后每条记录都是预测目标；历史 = 严格早于目标时刻的同组记录；
- test 目标 36,967 条（589 名学生），学生级 bootstrap 2,000 次（重采样单位 =
  test 学生，同一批权重用于所有模型 → 天然配对）。

## 3. 结果（assist2009，test 学生 36,967 条目标）

| 模型 | AUC [95% CI] | LogLoss [95% CI] | Brier | Accuracy | F1 |
|---|---|---|---|---|---|
| **GRU-DKT** | **0.7388** [0.7215, 0.7579] | **0.5420** [0.5257, 0.5572] | **0.1813** | **0.7336** | 0.8217 |
| BKT | 0.7093 [0.6925, 0.7283] | 0.5621 [0.5480, 0.5759] | 0.1895 | 0.7214 | 0.8126 |
| Rule-0 | 0.6946 [0.6770, 0.7151] | 0.6001 [0.5870, 0.6126] | 0.2061 | 0.7024 | 0.7875 |
| Majority | 0.5350 [0.5154, 0.5539] | 0.6330 [0.6218, 0.6450] | 0.2205 | 0.6771 | 0.8075 |

配对比较（同一目标集、同一批重采样权重，Δ = 行A − 行B；所有 CI 均不含 0）：

| 对比 | ΔAUC [95% CI] | ΔLogLoss [95% CI] |
|---|---|---|
| DKT − BKT | **+0.0294** [0.0230, 0.0361] | **−0.0202** [−0.0264, −0.0145] |
| DKT − Rule-0 | **+0.0441** [0.0369, 0.0512] | **−0.0580** [−0.0636, −0.0517] |
| DKT − Majority | +0.2040 [0.1799, 0.2308] | −0.0913 [−0.1081, −0.0775] |
| BKT − Rule-0 | +0.0147 [0.0091, 0.0204] | −0.0379 [−0.0436, −0.0318] |

**GRU-DKT 在学生级协议上同时取得最优的排序能力（AUC）与概率质量
（LogLoss / Brier），对 BKT 与 Rule-0 的优势 CI 均不含 0。**

分箱校准：DKT 全部 10 箱偏差 ≤ 0.04（各分箱预测 − 实际最大偏差 0.038），
是四个模型中校准最好的；Rule-0 低分区系统性低估依旧（[0.2,0.3) 箱：预测 0.243
vs 实际 0.420，低估 0.18），再次确认 guess 型机制（BKT 的 P(G)、DKT 的隐状态）
对概率质量的价值。

### 3.1 对四个核心问题的回答

1. **AUC 是否超过 Rule-0？** 在同一学生级协议上超过了
   （0.7388 vs 0.6946，ΔAUC = +0.0441，CI 不含 0）。
   注意：Rule-0 在 BKT 前后半段协议下的 0.7249 与本文数字**不可比**
   （目标集不同：那个协议含全部学生的评估段，本文只有 15% test 学生），
   两个协议的数字不得放进同一张表。
2. **LogLoss 是否超过 BKT？** 超过了（0.5420 vs 0.5621，ΔLogLoss = −0.0202）。
3. **是否利用了跨知识点信息？** DKT **具备**跨知识点建模能力——输入是
   全知识点交互序列（词表 200 个交互 id），隐状态跨知识点传递信息；
   BKT 每个知识点独立参数（100 组），Rule-0 只看同知识点近 10 次。
   但**当前实验不能证明"提升一定来自跨知识点信息"**——要归因需要消融实验
   （只保留同知识点历史 / 打乱知识点顺序 / 去掉 response 等），本文只能说
   DKT 具备该结构能力，提升来源待消融验证。
4. **是否真正有效而非过拟合？** 验证集 LogLoss 从 0.631（第 1 轮）单调降到
   0.546（第 46 轮），50 轮内未触发早停（训练/验证曲线同步下降，无过拟合
   迹象）；test LogLoss 0.542 与验证 0.546 一致，泛化正常。

### 3.2 结论表述（防止过度解读）

**结论限定：单数据集（ASSISTments 2009）、当前学生级 70/15/15 协议；
主结果（§3）为种子 42 单次训练，多种子重复实验见 §3.3。** 在该范围内：
基础 GRU-DKT（3 万参数）在排序能力和概率质量上均优于 BKT 与 Rule-0；
在固定种子 42 的学生级划分和本次训练配置下，DKT 的优势在配对 bootstrap
中具有统计稳定性（CI 不含 0）；**5 个随机种子的重复实验中该优势方向
5/5 一致且 CI 均不含 0（§3.3）**。不能写成"DKT 在所有协议、所有数据集
上都优于 BKT"。同时应说明：

- 优势幅度为 AUC +0.03~0.04，DKT 具备跨知识点建模的结构能力，但提升
  是否来自跨知识点信息共享需消融实验确认（见 §3.1 第 3 问），代价是
  失去知识点级参数的可解释性（BKT 能读出每个知识点的 P(L0)/P(T)/P(G)/P(S)，
  DKT 不能直接读出）；
- 跨数据集（Junyi / XES3G5M）验证属后续步骤。

### 3.3 多种子重复实验（种子 42/43/44/45/46）

针对单种子问题补做的重复实验：使用 **5 个随机种子**进行重复实验，
改变学生划分、参数初始化和训练随机过程（每个种子各自完成
「学生级 70/15/15 划分 → DKT 独立训练 → BKT 在该次 train 学生上重拟合 →
同一 test 目标集对照 → 2,000 次学生级 bootstrap」全流程）。
这些运行**共享同一数据集与同一组超参，不是统计意义上的完全独立实验**。

**注意两点口径**：①各种子的 test 学生集合不同，跨种子的绝对数字
不可配对比较，**也不得把 5 份 test 目标合并成一个「合并测试集」重算
总指标**，只能做「逐种子内部配对结论 + 跨种子方向一致性统计」；
②每个种子内部的配对 bootstrap CI 不含 0，只说明**该划分内**模型差异
稳定，**不是对 5 个种子均值进行的跨种子显著性检验**。

各模型跨种子表现（mean ± 总体标准差，n = 5；std 除以 n 而非 n−1，
描述这 5 次运行的实际波动）：

| 模型 | AUC (mean ± std) | LogLoss (mean ± std) |
|---|---|---|
| **GRU-DKT** | **0.7444 ± 0.0049** | **0.5384 ± 0.0039** |
| BKT | 0.7157 ± 0.0061 | 0.5588 ± 0.0051 |
| Rule-0 | 0.7010 ± 0.0055 | 0.5961 ± 0.0044 |
| Majority | 0.5437 ± 0.0099 | 0.6335 ± 0.0041 |

逐种子配对差（ΔAUC = DKT − 对照，95% CI）：

| 种子 | DKT − BKT ΔAUC | DKT − Rule-0 ΔAUC | DKT − BKT ΔLogLoss | DKT − Rule-0 ΔLogLoss |
|---|---|---|---|---|
| 42 | +0.0294 [+0.0230, +0.0361] | +0.0441 [+0.0369, +0.0512] | −0.0202 | −0.0580 |
| 43 | +0.0275 [+0.0226, +0.0325] | +0.0450 [+0.0393, +0.0507] | −0.0216 | −0.0593 |
| 44 | +0.0267 [+0.0226, +0.0313] | +0.0433 [+0.0381, +0.0482] | −0.0185 | −0.0593 |
| 45 | +0.0330 [+0.0273, +0.0388] | +0.0432 [+0.0369, +0.0492] | −0.0220 | −0.0568 |
| 46 | +0.0265 [+0.0214, +0.0317] | +0.0412 [+0.0347, +0.0477] | −0.0194 | −0.0545 |

**方向一致性：5/5 种子中 DKT − BKT 与 DKT − Rule-0 的 ΔAUC 全为正、
ΔLogLoss 全为负，且每个种子的配对 CI 均不含 0**（BKT − Rule-0、
DKT − Majority 同样 5/5 方向一致）。DKT 的优势量级在不同学生划分与
不同初始化下非常稳定（ΔAUC 波动 ≤0.004）。据此可以写：**在 ASSISTments
2009 的学生级 70/15/15 协议下，GRU-DKT 相比 BKT 和 Rule-0 的优势在
5 个随机种子中方向一致，且每个种子的学生级配对 bootstrap 置信区间均
支持该优势**——这不是跨种子显著性检验，只是 5 次重复实验中结论方向
与种子内统计稳定性的一致呈现。

汇总文件：`backend/实验结果文件/baseline-results-dkt-assist2009-multiseed.json`
（汇总脚本 `backend/models/aggregateDktSeeds.js`）。
**结论仍限定在单数据集（ASSISTments 2009）与当前学生级协议**；
跨数据集验证仍是后续步骤。

## 5. 已知限制

1. **协议不可比**：本文数字与 BKT 说明文档（估计段协议）的数字不可直接互比，
   跨模型结论以本文同一目标集上的配对比较为准；
2. **多种子已做、但仍有限**：§3.3 覆盖了 5 个种子的划分/初始化稳定性，
   但每个种子仍是单次训练（未对同一划分做多次重复训练估计训练噪声），
   且超参未逐种子调优（所有种子共用同一组超参，这本身是一种约束）；
3. **序列长度截断未做**：长序列学生全序列参与 BPTT（本数据集最长数百步，
   实测可承受）；梯度消失/爆炸由裁剪兜底，但超长序列的记忆能力未专门验证；
4. **无真实时间**：与 BKT/Rule-2 相同，数据集无真实时间戳，时间衰减类组件
   不可评估；
5. **可解释性**：DKT 输出不可分解为知识点级参数，用于推荐解释时需要
   辅助手段（如隐状态相似度），这一点与 BKT 的分工见对齐说明。
