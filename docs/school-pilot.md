# 学校试用说明

当前版本支持单学校、小范围试用。完成了软件流程改造，不代表题库已通过教师审核，也不代表学习效果已经得到验证。

## 开始使用

1. 管理员在「用户管理」创建教师账号；教师创建班级和学生账号。
2. 教师在「班级管理 → 已学范围」填写实际教材版本，选择已经学过的知识点。目录中年级仅为建议，以教师核对的教学进度为准。
3. 在「题库与审核」核对题干、选项、答案、解析、知识点和难度。补充几何附图、分步提示、可接受答案；解答题可设置步骤分值。审核通过后才进入作业和补练。
4. 发布作业。学生作答时草稿自动同步，并在断网时保存到当前浏览器；交卷有唯一提交编号，重试不会重复统计。退出账号会清除本机草稿，服务器草稿继续保留。
5. 教师在「复核与纠错」处理作业、专项练习和图片答卷。复核后同步成绩、错题本和掌握度，重复复核不会增加作答次数。
6. 学生进行已学范围内的针对性补练。推荐避开刚作答的题和当天已推送的题，不跨越教师设置的已学范围。工作台显示复习计划；按间隔作答表现安排 1、3、7、15 天后的复习，同一天重复答对不会直接把错题标成已掌握。

## 数据和权限

- 题目与所有业务集合保存在 SQLite；重启不再重置账号、班级、作业、答题、草稿、错题或学情。服务启动时不会重建并覆盖已有练习题。
- 默认开发环境仍有演示账号，演示账号初始没有虚构答卷和学情。启动时只补充缺失的题库初始化数据一次。
- 登录令牌和 HttpOnly 会话 Cookie 都须由后端验证。身份以令牌对应账号为准，不信任客户端发送的用户 ID。学生只能访问自己的记录；教师只能访问授权班级。
- 未作答的知识点显示「尚未测评」。最近 10 次有效作答不足 5 次，或不同题目不足 3 道时，显示「样本不足」，不会认定已掌握。此阈值是可解释的试用规则，仍需通过教学验证校准。
- 教师学情与学生页面使用同一个掌握度计算；作业成绩比较按满分换算为百分比。等待复核的提交不纳入最终成绩趋势。
- 学生请求题目时不返回标准答案、解析、可接受答案和评分参考。图片访问需登录，学生作答图片只向本人及授权教师开放。
- 管理员可以停用账号、重设密码、导出学生数据，以及删除账号和关联学习记录。删除教师账号前需要移交班级。日志不存储明文密码、令牌或服务密钥。

## 备份与恢复

「系统设置 → 数据备份与恢复」可以下载 JSON 数据备份。备份含账号密码哈希和学习记录，只应由管理员保管。

恢复前先下载当前备份。恢复会校验数据集合和管理员账号，并在事务中更新业务集合与题库。恢复成功后核对账号、班级、答卷及抽样成绩。

JSON 备份不含图片二进制文件；还需单独备份 `backend/uploads/`。本地 SQLite 自动创建的 WAL 文件不应单独提交到仓库。拷贝数据库文件前应停止服务，或采用 SQLite 的一致性备份机制。

## 正式部署配置

开发服务默认仅监听本机，避免演示账号暴露到网络。配置 `NODE_ENV=production`、随机且至少 32 字符的 `JWT_SECRET`、准确的 `WEB_ORIGIN`，并通过 HTTPS 访问。使用独立 `DATA_DIR`，初次初始化设置至少 12 位的 `ADMIN_PASSWORD`。生产环境不会创建演示师生账号，并禁止仍使用已知默认密码的数据库。

示例环境配置见 `backend/.env.example`。服务密钥、数据库、上传文件和备份不能提交到代码仓库。

## 教学内容边界

- 当前目录由 18 个节点扩展到 30 个常见知识主题，提供年级建议和前置关系；不是任何具体教材的完整章节目录。使用前按学校教材核对，补充细分知识点和足量审核题目。管理员可在「知识点管理」维护目录、年级建议及前置关系，修改会共享给题库、已学范围和学情统计。
- 原预置题全部标记为待审核。已修正 `y=-x+4` 图像经过象限的错误，但没有把程序检查包装成教师审核。
- 填空题支持精确分数、小数和有界多项式等价比较，以及教师录入的可接受答案。含程序暂不支持的根式、三角函数等表示、且不能直接匹配的答案转入复核。解答题始终由教师复核过程，不能依据文字相似度直接给最终分。
- 图片上传用于人工复核，当前不声称 OCR 能可靠识别或批改手写数学。

## 小范围试用验收

先选一个班的一个已学章节，由数学教师审核题目。记录题目纠错率、自动判分与教师判分分歧、草稿恢复成功率、练习完成率、复习后独立作答情况及教师处理时间。用这些证据决定是否扩展范围；不用上线按钮、测试通过或页面上的掌握度代替学习效果验证。

软件验证：后端包含身份伪造、跨班访问、答案隐藏、重复提交、步骤复核、备份恢复、跨进程持久化、无数据状态和数学等价判断测试。测试数据库使用独立临时目录。

可运行隔离的浏览器验收环境：先执行 `node backend/test/browser-fixture.js`（API 5002），再在 frontend 目录设置 `BACKEND_TARGET=http://127.0.0.1:5002` 后运行 `npx vite --port 5003`，访问 `http://localhost:5003`。这套作业用于验证软件流程，不记录到学校数据库。
