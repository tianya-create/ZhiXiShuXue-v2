# DKT 消融实验说明（Same-KP / Shuffled-KP / NoResponse）

> **协议版本 v2（2026-10-30 修订）**：`dkt-ablation-v2-input-kp-only`。
> 审查发现 v1 的 Shuffled-KP 把「历史输入知识点」与「预测目标端口知识点」混用同一字段：
> 打乱历史标签的同时，约 81% 测试目标（seed 42：36,967 条中 29,914 条）的输出端口被一并改变，
> 其差异不能解释为「历史顺序信息」的贡献。v2 将两者分离（`inputKpCode` 只进输入编码，
> `kpCode` 只决定输出端口与目标身份）并在新目录重跑全部四模式五种子。
> **v1 结果保留在原目录仅作旧协议对照，不与 v2 混表。**

## 1. 目的与定位

消融实验要回答三个问题：

1. DKT 的优势是否来自**跨知识点历史**（看到其他知识点的答题记录）？
2. 是否来自**真实的知识点转移顺序**（知识点在时间上的排列）？
3. 是否主要来自**作答结果本身**（历史对错），而不是知识点序列？

定位：这是**消融实验**，不是新模型。它决定「是否值得引入知识点图结构（GCN-DKT）」——
如果跨知识点历史没有稳定贡献，图结构（本质是更强的跨知识点信息传递）缺少前提。

## 2. 统一协议

与 GRU-DKT 正式实验（`docs/GRU-DKT对照实验说明.md`）**完全一致**：

- 学生级 70/15/15 划分，同一 `--seed` 控制划分、参数初始化、dropout 与批次洗牌；
- 同一学生不跨 train / validation / test；train 训练、validation 早停、test 只做最终评估；
- 固定超参：embedding 32、GRU hidden 64、dropout 0.2、lr 1e-3、batch 64、
  最多 50 epoch、patience 5、梯度裁剪 5.0；
- 目标集：test 学生中「非 (学生, 知识点) 组首条」的记录，**四种模式逐条对齐同一批目标身份**（学生 + 答题时刻）；
- 学生级 bootstrap 2,000 次（重采样单位 = test 学生），**同一批权重用于四个模型** → 天然配对；
- 报告 AUC / LogLoss / Brier / Accuracy / F1、目标数、训练轮数，以及相对 Full-DKT 的配对差值。

可行性保证（代码层面）：

- 四个模型在**同一进程内顺序训练**，共用同一份数据、划分、目标集与 bootstrap 权重；
- 模型之间不共享参数，各自用同一 `--seed` 初始化；
- 训练序列顺序与 `dktEval.js` **完全一致**（按 `split.train` 的乱序 id 顺序取），
  因此 Full-DKT 与正式 DKT 结果逐位一致（见 §4 自校验），避免「同一配置两个数字」的解释成本。

## 3. 四种输入模式（统一 inputMode 接口）

实现上抽取统一接口，**没有复制四套 GRU**：

| 层次 | 统一入口 | 各模式差异 |
|---|---|---|
| 词表 | `buildVocab(seqs, { inputMode })` | `no-response` 用独立词表（大小 = 知识点数） |
| 编码 | `encodeInteractionId(kpIndex, kp, correct, mode)` | `no-response` 返回 `kpIndex`，不含 response 位 |
| 序列 | `transformSequences(seqs, mode, { shuffleSeed })` | `same-kp` 拆组、`shuffled-kp` 打乱标签、`full`/`no-response` 不变 |
| 预测收集 | `collectPredictions(model, seqs, { targetIds })` | 四种模式统一按「学生+时刻」对齐到同一目标集 |

四种模式（v2 字段语义）：

1. **Full-DKT**（参照）：知识点 + response + 原始学生序列。
2. **Same-KP-DKT**：把学生序列拆成 (学生, 知识点) 子序列，模型只看得到**同一知识点内**的历史，
   其他知识点的交互完全不进入该次预测。子序列位置 0 即该组首条记录，
   因此可预测位（t ≥ 1）**恰好等于**「非组首条」的目标集，与 Full-DKT 逐条对齐。
   注意：Same-KP 的训练与验证监督位置与整序列模式**不完全相同**
   （按子序列计 t ≥ 1，见结果 JSON 中各模型的 `supervisionCounts`），
   其差异同时受历史长度、序列切分与优化过程影响，不能全部归因于「跨知识点信息」本身。
3. **Shuffled-KP-DKT**（v2）：在每个学生内部**只置换历史输入知识点 `inputKpCode`**，
   `kpCode`（原始目标知识点 / 输出端口）、response 序列、时间顺序、目标身份与标签全部不变。
   变换种子 = `--seed` 与 `userId` 混合（独立于训练随机流），可复现。
   这是**离线置换对照**：使用整名学生的 KP 多重集，可能把未来才出现的 KP 放进较早的
   输入位置，**不构成严格前缀可见的在线预测协议**（见 §7）。
4. **NoResponse-DKT**：保留知识点序列，但**不把历史 response 作为模型输入**（独立词表，
   id = kpIndex，不会把「没有 response」编码成「真实答错」）；
   **真实 response 仍用于训练监督、验证早停与测试评分**；输出层仍按知识点。

## 4. 测试与自校验

`backend/test/dktAblation.test.js` 覆盖方案要求的检查（v2 共 17 项，全部通过）：

| 检查 | 做法 |
|---|---|
| 目标数量一致 | 四种模式在固定数据集上预测覆盖数 = 目标数（缺一条即报错退出） |
| 学生划分一致 | 四模式共用同一 `splitStudents` 结果，逐行校验 `userId` 相同 |
| 标签一致 | 逐行校验 `target` 与参照模型完全相同 |
| **Shuffle 只改历史输入 KP** | 变换前后 `kpCode`/`correct`/`ts`/`record` 逐项不变，仅 `inputKpCode` 置换且保每学生频数 |
| **目标端口反例** | `Wout` 全置零、各 KP 输出偏置不同 → Full 与 Shuffle 的同一目标预测完全相同（都取原始 KP 偏置） |
| **当前输入不泄漏** | 只改 t 时刻 `inputKpCode` → t 的预测不变，后续预测可变 |
| **训练端口正确** | 目标 KP 固定为 B、输入 KP 改成 A → 一个 epoch 后 `bout` 只有 B 被更新 |
| Same-KP 不读其他知识点 | 固定权重，把其他 KP 的作答取反 → 目标 KP 预测完全不变；Full 会变 |
| **NoResponse 固定权重不变性** | 固定同一组（随机初始化、未训练）权重，翻转全部历史 response → 预测逐项相同 |
| Shuffle 可复现 / 保频数 | 同一 `shuffleSeed` 两次变换相同；不同 seed 不同排列；输入 KP 频数不变 |
| 端到端 | synthetic 小数据跑通 CLI：新字段（protocolVersion / supervisionCounts / 逐目标预测 JSONL / 目标 manifest）齐全 |
| **错位 checkpoint 拒绝恢复** | 篡改断点中两条同标签目标的身份 → 行数与标签不变仍被逐行校验拒绝并重训 |

额外的**审计自校验**（实现阶段发现并修复的问题）：最初本脚本按学生字典序取训练序列，
与 `dktEval.js` 按 `split.train` 顺序取不同，导致 Full-DKT 在同一种子下与正式结果
不逐位一致（best epoch 48 / val 0.546621 vs 46 / 0.5463）。修正为同一顺序后，
seed 42 的前 3 轮 train/val LogLoss 与 `baseline-results-dkt-assist2009.json`
中记录的曲线**逐位相同**（0.664482 / 0.630902、0.599279 / 0.591661、0.573958 / 0.575613）。
这保证了「Full-DKT 消融参照 = 正式 DKT 结果」不是近似，而是同一模型。

## 5. 结果

### 5.0 v1 结果（旧协议，保留作对照，不进主表）

> 以下为 v1 协议数字。其中 **Shuffled-KP 一行的语义是「全序列 KP 标签置换，
> 含当前目标 KP 扰动」**——它同时改变了约 81% 测试目标的输出端口，
> 因此该行数字**不能**用于推断「历史知识点顺序」的贡献，仅作实现历史留档。
> Full / Same-KP / NoResponse 三行的预测语义与 v2 相同，可作参考。

数据集：ASSISTments 2009（266,948 条记录 / 3,931 名学生）；5 个随机种子（42–46）重复，
每个种子四模式同进程训练，种子间口径为 mean ± 总体标准差（÷n）。

审计自校验（v1）：**5 个种子的 Full-DKT 均与 `dktEval` 正式结果逐位一致**
（AUC / LogLoss / best epoch / best val 全部相同），消融参照 = 正式 DKT 模型，不是近似。

### 5.1 四模式指标（5 种子 mean ± std，test 学生目标集）

| 模型 | AUC | LogLoss | Brier | Accuracy | F1 |
|---|---|---|---|---|---|
| **Full-DKT**（参照） | **0.7444 ± 0.0049** | **0.5384 ± 0.0039** | 0.1797 | 0.7362 | 0.8224 |
| Same-KP-DKT | 0.7342 ± 0.0047 | 0.5461 ± 0.0035 | 0.1826 | 0.7314 | 0.8201 |
| Shuffled-KP-DKT | 0.7144 ± 0.0038 | 0.5562 ± 0.0054 | 0.1866 | 0.7291 | 0.8203 |
| NoResponse-DKT | 0.6767 ± 0.0064 | 0.5857 ± 0.0058 | 0.2001 | 0.6947 | 0.8010 |

Full-DKT 与 DKT 正式多种子实验结果完全一致（0.7444 ± 0.0049 / 0.5384 ± 0.0039），
交叉验证了消融协议的正确性。

### 5.2 相对 Full-DKT 的配对差值（Δ 统一为「Full-DKT − 消融」）

| 比较 | 逐种子 ΔAUC（s42→s46） | ΔAUC>0 | ΔAUC CI 排除 0 | 逐种子 ΔLogLoss（负 = Full 更好） | ΔLL CI 排除 0 |
|---|---|---|---|---|---|
| Full − Same-KP | 0.0079, 0.0074, 0.0101, 0.0127, 0.0127 | **5/5** | **5/5** | −0.0068, −0.0067, −0.0079, −0.0081, −0.0089 | **5/5** |
| Full − Shuffled-KP | 0.0307, 0.0339, 0.0267, 0.0270, 0.0319 | **5/5** | **5/5** | −0.0185, −0.0202, −0.0155, −0.0180, −0.0161 | **5/5** |
| Full − NoResponse | 0.0663, 0.0663, 0.0629, 0.0765, 0.0663 | **5/5** | **5/5** | −0.0446, −0.0493, −0.0424, −0.0500, −0.0503 | **5/5** |

说明：LogLoss 越低越好，ΔLogLoss 为负表示 Full-DKT 更好。三个比较在全部 5 个种子中
方向一致（AUC 更高、LogLoss 更低），且每个种子内部的配对 bootstrap CI 均不含 0。

### 5.3 v1 结论标注（已被 v2 取代，仅留档）

v1 曾据此写「Shuffled-KP 差值 = 真实知识点转移顺序的贡献」——该解读**不成立**
（目标端口被同时扰动）。v2 重跑后的结论见 §5.4。

### 5.4 v2 结果（dkt-ablation-v2-input-kp-only，主表）

数据集与种子口径同 §5.0：ASSISTments 2009，5 个随机种子（42–46），
四模式同进程训练，种子间口径为 mean ± 总体标准差（÷n）。

审计自校验（v2）：**5 个种子的 Full-DKT 均与 `dktEval` 正式结果逐位一致**
（AUC / LogLoss / best epoch / best val 全部相同）。同时 v2 的 Full / Same-KP /
NoResponse 三模式逐种子指标与 v1 **完全相同**——证明修复只改变了 Shuffled-KP
的预测语义，其余模式未受影响。

#### 四模式指标（5 种子 mean ± std）

| 模型 | AUC | LogLoss |
|---|---|---|
| **Full-DKT**（参照） | **0.7444 ± 0.0049** | **0.5384 ± 0.0039** |
| Same-KP-DKT（屏蔽跨知识点历史） | 0.7342 ± 0.0047 | 0.5461 ± 0.0035 |
| Shuffled-KP-DKT（仅置换历史输入 KP） | 0.7425 ± 0.0043 | 0.5394 ± 0.0041 |
| NoResponse-DKT（不给对错反馈） | 0.6767 ± 0.0064 | 0.5857 ± 0.0058 |

#### 相对 Full-DKT 的配对差值（点估计差；ΔAUC > 0 / ΔLogLoss < 0 = Full 更好）

| 比较 | 逐种子 ΔAUC（s42→s46） | ΔAUC>0 | AUC CI 排除 0 | 逐种子 ΔLogLoss | LL CI 排除 0 |
|---|---|---|---|---|---|
| Full − Same-KP | 0.0079, 0.0074, 0.0102, 0.0128, 0.0127 | **5/5** | **5/5** | −0.0067, −0.0066, −0.0079, −0.0081, −0.0089 | **5/5** |
| Full − Shuffled-KP | 0.0013, 0.0005, 0.0013, 0.0019, 0.0045 | 5/5 | **1/5** | −0.0004, −0.0004, −0.0005, −0.0020, −0.0013 | **0/5** |
| Full − NoResponse | 0.0665, 0.0661, 0.0630, 0.0765, 0.0664 | **5/5** | **5/5** | −0.0445, −0.0491, −0.0425, −0.0497, −0.0503 | **5/5** |

### 5.5 v2 结构化结论（按 §6 预先声明的判定规则）

1. **历史对错（response）贡献最大**：NoResponse 后 ΔAUC = +0.0677，
   5/5 方向一致、逐种子 CI 全部排除 0 → response 是 DKT 最重要的信息来源；
2. **Same-KP 对照下观察到稳定性能差异**：Same-KP 后 ΔAUC = +0.0102，
   5/5 方向一致、逐种子 CI 全部排除 0 → 在此对照下 Full-DKT 稳定更好。
   注意（§7.1）：Same-KP 同时缩短了可用历史，该差异不能 100% 归因于
   「跨知识点信息」本身，也包含序列长度/训练数据量的影响；
3. **历史知识点顺序未观察到稳定边际收益**：Shuffled-KP（仅置换历史输入 KP）
   后 ΔAUC 仅 +0.0019，方向虽在 5/5 种子为正，但逐种子 CI 仅 1/5 排除 0、
   ΔLogLoss CI 0/5 排除 0。按 §6 判定规则，**不能声称「真实知识点顺序」
   有独立贡献**；只能说在当前数据规模与短序列条件下，置换历史输入 KP 标签
   未带来稳定伤害。

对 GCN-DKT 的含义（**待验证假设**，现有消融不能直接证明 GCN-DKT 的收益来源）：

- Same-KP 对照下观察到稳定性能差异 → 图结构若能把跨知识点关系
  显式注入并与作答历史协同，**有前提**（前提成立与否仍需 GCN-DKT 实验本身验证）；
- §5.5.3 提示：仅置换「历史 KP 标签的排列顺序」未观察到稳定影响，由此猜测
  图结构的价值（若有）更多来自「哪些知识点相关」（结构先验），
  而不是「历史里知识点出现的先后顺序」——这只是**待验证假设**，
  需由 GCN-DKT 与本消融的对照实验检验；
- NoResponse 差距最大 → 任何图结构增强都不应以牺牲 response 输入为代价
  （这一条是消融直接观察，非假设）。

**结论限定**：以上为单数据集（ASSISTments 2009）、当前学生级协议、
5 个随机种子（非统计独立）下的结论，不外推到其他数据集或协议；
各种子的配对 CI 只说明该划分内差异稳定，不是跨种子显著性检验。

## 6. 判定规则（预先声明，避免事后挑结论）

- 只有当「Full-DKT − 消融」的优势在**多数种子中方向一致**、且**配对 CI 多数不含 0** 时，
  才可以说该信息源有独立贡献；
- 若差异很小或方向不一致，如实写：在当前数据规模、短序列条件下，
  该信息源未观察到稳定边际收益；
- 结果为「单数据集（ASSISTments 2009）+ 当前学生级协议 + 5 个随机种子」的结论，
  不外推到其他数据集；
- 各种子的 test 学生集合不同：跨种子只统计方向，**不把多份 test 目标合并重算总指标**，
  每个种子的配对 CI 也不是跨种子显著性检验。

## 7. 已知限制

1. **Same-KP 的序列变短**：拆组后模型可用的历史更少，这本身是「屏蔽其他知识点」的必然结果，
   但它同时降低了训练 token 数与有效样本量，差异不能 100% 归因于「跨知识点信息」本身
   （也包含「序列长度/训练数据量」的影响）。要分离两者需要额外做「等长度随机子序列」对照，
   列入后续工作；
2. **Shuffled-KP 是离线置换对照，不是纯顺序因果实验**：置换用整名学生的 KP 多重集，
   可能把未来才出现的 KP 放进较早输入位置（非前缀可见）；且置换同时破坏了
   历史 KP 与 response 的对应关系，不是只改变一种抽象的「顺序」。可写「历史知识点与
   作答位置/结果的对应关系包含预测信息」，**不可写**「单独证明了真实知识点转移顺序的
   因果贡献」。严格在线对照需另设只依赖可见前缀的扰动方案，单独命名和报告；
3. **NoResponse 仍含知识点难度信息**：输出层按知识点、输入含知识点 id，
   因此它变弱说明「对错历史」重要，但变强也不能解释为「知识点无信息」；
   真实 response 仍用于训练监督、验证早停与测试评分；
4. **单数据集、单组超参**：超参沿用 DKT 正式实验，未逐消融模式调优（一致的超参是公平性要求，
   但也可能低估某些模式的潜力）；
5. **四模式共享同一划分与测试目标，但训练/验证监督位置不完全一致**：Same-KP 按
   (学生,KP) 子序列计监督位（见 `supervisionCounts`），差异含序列切分与优化过程影响。
   统一全部监督目标属 v3 协议增强，不与 v2 混表；
6. **划分噪声**：划分固定后，消融差异不包含划分噪声；划分噪声已在
   5 种子重复中体现。

## 8. 复现命令与产出

```bash
cd backend
# v2 协议（主结果目录 实验结果文件/v2-input-kp-only/）：
# 单个种子（约 1.5 小时：四个模型顺序训练，纯 JS；中断后同命令重跑即从断点续训）
node models/dktAblation.js --source csv \
  --file datasets/assist2009/interactions.csv \
  --seed 42 --bootstrap 2000 --label dkt-ablation-s42 \
  --out 实验结果文件/v2-input-kp-only

# 5 个种子聚合（--input-dir 指向 v2 目录，拒绝与旧协议混表）
node models/aggregateDktAblation.js --seeds 42,43,44,45,46 \
  --input-dir 实验结果文件/v2-input-kp-only \
  --out 实验结果文件/v2-input-kp-only/baseline-results-dkt-ablation-multiseed.json
```

产出：

- `backend/实验结果文件/v2-input-kp-only/baseline-results-dkt-ablation-s{42..46}.json`：
  每个种子的四模式指标、CI、配对比较（点估计差 + bootstrap 均值分开）、训练曲线、
  `supervisionCounts`、协议版本与可复现性哈希；
- 同目录 `ablation-predictions-<label>.jsonl`（逐目标四模式预测，可独立重算 CI）、
  `ablation-targets-<label>.json`（目标 manifest，含目标身份/原始 KP/标签）；
- `backend/实验结果文件/v2-input-kp-only/baseline-results-dkt-ablation-multiseed.json`：
